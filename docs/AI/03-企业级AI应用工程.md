# 大型企业级 AI 应用工程能力

## 1. 参考架构

```text
Web / App
  -> API Gateway / BFF（认证、配额、限流）
  -> AI Orchestrator（工作流、上下文、模型路由、策略）
       -> Model Gateway（多模型、重试、成本、版本）
       -> Retrieval Service（解析、索引、搜索、rerank）
       -> Tool Services（业务 API，独立鉴权）
       -> Conversation / Memory Store
  -> Queue / Workers（文档解析、Embedding、长任务）
  -> Observability & Evaluation（trace、指标、数据集、告警）
```

早期不必拆成微服务。可以在 FastAPI 单体内保持模块边界，等到团队所有权、独立扩容或故障隔离确有需要时再拆分。

## 2. 必须掌握的工程主题

### 模型与供应商治理

模型抽象、能力/成本/延迟路由、版本固定、灰度、fallback、配额和供应商故障处理。不要假设不同模型的 Tool Calling、JSON Schema 和 token 规则完全一致。

### 数据与知识管道

数据源连接、解析、OCR、去重、分块、元数据、ACL 同步、增量索引、删除传播、版本和数据血缘。用户无权查看的文档，绝不能只在生成答案后再过滤。

### 异步任务与可靠性

Embedding、批量摄取和长 Agent 任务使用队列/Worker。掌握至少一次投递、幂等、重试、死信队列、任务状态、取消和补偿。外部 API 必须有连接/读取超时、退避、熔断和并发隔离。

### 多租户和权限

租户隔离、RBAC/ABAC、行级/文档级权限、服务身份、短期凭据和审计日志。工具执行必须以当前用户或受约束服务身份授权，不能因为“模型要求”而越权。

### API 与状态设计

会话、消息、run、step、tool-call 分开建模；长任务支持排队、运行、等待确认、成功、失败、取消等状态。写工具需要幂等键，审批后恢复执行需要可持久化 checkpoint。

## 3. 安全威胁模型

必须学习 OWASP Top 10 for LLM Applications，并重点防范：

- Prompt Injection：用户或检索文档诱导模型忽略规则。
- Data Exfiltration：模型通过工具或回答泄露其他用户、租户或系统提示中的数据。
- Excessive Agency：工具权限过大、无需确认即可产生高影响副作用。
- Insecure Output Handling：把模型输出直接作为 SQL、HTML、Shell 或下游指令执行。
- Poisoning / Supply Chain：知识库被投毒，模型、依赖或 MCP/工具来源不可信。
- Denial of Wallet：恶意长输入、循环工具调用导致费用和资源耗尽。

防线必须在代码和基础设施中：输入大小限制、输出编码、参数化查询、工具白名单、网络出口策略、最小权限、密钥管理、PII 脱敏、内容审核、预算上限和人工审批。Prompt 只能作为其中一层。

## 4. 评测体系

没有评测集就无法可靠优化。建立来自真实业务的版本化数据集，至少包含：正常问题、同义表达、无答案、冲突证据、多轮追问、权限问题、提示注入和工具失败。

评测分层：

| 层 | 指标示例 |
| --- | --- |
| 检索 | Recall@k、MRR、过滤正确率、引用覆盖率 |
| 生成 | groundedness、完整性、格式通过率、拒答正确率 |
| 工具 | 选对工具率、参数正确率、任务成功率、副作用安全性 |
| 系统 | P50/P95 延迟、错误率、可用性、每次成功任务成本 |
| 产品 | 问题解决率、追问率、点赞/踩、人工接管率 |

LLM-as-judge 可用于规模化辅助评估，但会有偏差，必须用人工标注样本校准。上线前跑离线回归，上线后做小流量灰度和在线反馈；Prompt、模型、索引配置变化都应可追踪和回滚。

## 5. 可观测性

一次请求需要关联：用户/租户（脱敏）、conversation、run、模型、Prompt 版本、检索 query 与文档 ID、工具调用、token、费用、延迟、重试和最终状态。生产日志默认不记录完整敏感 Prompt、Token、密钥或私人文档正文。

使用 OpenTelemetry 贯通 HTTP、数据库、检索、模型和工具调用；建立延迟、错误、token、成本、队列积压和安全事件告警。Trace 数据也受数据保留与访问控制约束。

## 6. 性能与成本

常见手段包括：小模型路由、缩短上下文、缓存 Embedding、语义/精确缓存、批量 Embedding、并行执行独立读工具、流式返回和限制 Agent 步数。缓存必须把租户、权限、模型/Prompt 版本和知识版本纳入 key，避免数据串租户或返回过期答案。

优化目标应是“每个成功任务的成本”，而不是只看每百万 token 单价。质量下降造成的人工返工也属于成本。

## 7. CI/CD 与发布治理

- 单元测试验证解析、切块、工具参数、权限和状态机。
- 集成测试使用可控模型 stub 与测试数据库，避免测试随机失败和失控费用。
- 少量端到端测试调用真实模型，设置预算并容忍非关键文字差异。
- Prompt、评测集、模型配置和索引 schema 纳入版本管理。
- 发布使用离线评测门禁、canary、功能开关、回滚和供应商故障演练。

## 8. 企业岗位还会考察什么

除 AI 专题外，还要具备传统分布式系统基础：HTTP、网络、数据库索引与事务、缓存一致性、消息队列、并发、CAP/可用性取舍、身份认证、云服务、容器和 Kubernetes 基础。AI 应用仍然是软件系统，模型只是其中一个不确定且昂贵的依赖。
