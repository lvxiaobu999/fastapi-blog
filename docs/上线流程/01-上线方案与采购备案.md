# 上线方案与采购备案

本章先回答三个问题：网站由谁运营、部署在哪个地域、要购买哪些资源。架构和地域一旦选错，
后面备案、网络和迁移都会返工。

## 1. 先决定主体和地域

### 1.1 运营主体

在购买前记录：

- 个人还是企业主体。
- 域名实名认证主体。
- ICP 备案主体和网站负责人。
- 阿里云账号实名主体与付款主体。
- 告警、续费、安全事件和数据恢复负责人。

域名实名与备案主体尽量保持一致。主体名称、证件、联系方式或网站服务内容不一致可能导致
备案退回。

### 1.2 中国大陆还是香港/海外

| 选择 | 优点 | 代价 |
|---|---|---|
| 中国大陆地域 | 大陆用户网络通常更稳定，可使用完整大陆云生态 | 正式对外服务前通常需要 ICP 备案 |
| 中国香港/海外 | 通常不需要大陆 ICP 备案即可部署 | 大陆访问延迟、稳定性和合规边界不能等同大陆节点 |

本文后续按“中国大陆 ECS 正式上线”编写。不准备备案时可以选择香港/海外，但不要把它当成
规避其他数据、内容或经营合规要求的办法。

## 2. 当前选择：ECS + Docker 自建 PostgreSQL/Redis

当前项目有这些运行特征：

- FastAPI 依赖 Python 3.13 和 uv 锁文件。
- 生产 Settings 强制 PostgreSQL `postgresql+psycopg://`。
- Refresh Session 强依赖 Redis、TTL、Set 和 Lua `EVAL`。
- WebSocket 评论连接是长连接，房间状态在单进程内存。
- 头像和文章图片写入 `app/media`。
- Alembic 需要作为单独发布步骤执行。

因此当前低成本上线采用：

```text
一台 ECS：Docker + FastAPI + Nginx + PostgreSQL + Redis
一个 ECS 数据目录/数据盘：PostgreSQL、Redis AOF 和 media
```

轻量应用服务器也能演示，但 Docker 磁盘、网络和安全组能力要先核对；ACK/Kubernetes 对当前
单体学习项目又过重。未来预算允许时，再评估迁移到 RDS/Tair 等托管服务。

## 3. 采购清单

### 3.1 必选资源

| 资源 | 购买时关注 | 项目用途 |
|---|---|---|
| 域名 | 后缀、续费价、实名认证、自动续费 | 网站入口和备案 |
| VPC/交换机/安全组 | 地域、CIDR、可用区 | ECS 网络隔离 |
| ECS | CPU、内存、系统盘、数据盘、公网带宽 | 运行四个容器并构建镜像 |
| 固定公网 IP/EIP | 带宽计费、峰值、是否会变化 | DNS 的稳定目标 |
| 数据盘/快照 | 容量、IOPS、快照策略 | PostgreSQL、Redis、media 持久化 |
| SSL 证书 | 覆盖准确域名、有效期、续签方式 | HTTPS 和 `Secure` Cookie |

### 3.2 推荐资源

| 资源 | 何时需要 |
|---|---|
| ECS 数据盘和快照 | 希望上传文件与系统盘故障隔离 |
| OSS | 准备异地备份或将来多实例 |
| SLS | 需要集中查询 JSON 日志和 request_id |
| 云监控/云安全中心 | 正式公网服务应至少启用基础告警 |
| CDN/WAF/SLB | 流量、攻击风险或多实例出现后再引入 |

## 4. 起步规格

个人博客可以把 2 vCPU、4 GiB 内存作为评估起点，但不要只看应用空闲内存：Docker 镜像构建、
PostgreSQL、Redis、Nginx 和峰值请求都会占资源。数据库和 Redis 与应用共用 ECS，内存不足会同时影响四个容器。

规格不是固定答案。购买前检查：

- ECS 构建一次镜像所需磁盘空间和内存。
- PostgreSQL/Redis 数据目录所需磁盘空间、IOPS 和备份空间。
- Redis 最大内存、AOF 增长和淘汰策略；当前代码需要 Lua `EVAL`。
- 公网带宽计费方式、峰值和出网费用。
- 包年包月到期、自动续费、快照、备份、SLS 和公网流量的额外费用。

具体价格和可售版本会变化，文档不写死价格。

## 5. 地域、VPC 和可用区

ECS 单机方案只需保证 ECS 网络和数据盘可用；不再需要为 RDS/Tair 单独配置 VPC 白名单：

```text
ECS
  -> 系统盘/数据盘可用
  -> 安全组只开放 22/80/443
  -> Docker backend 网络隔离 postgres/redis
```

PostgreSQL、Redis 不映射宿主机端口，app 通过 Compose 服务名 `postgres`、`redis` 连接；不要
为了远程管理临时开放 5432/6379。

## 6. 推荐购买顺序

1. 确定主体、地域、预算和域名。
2. 购买并实名认证域名，开启到期提醒/自动续费。
3. 创建 VPC、交换机和 ECS 安全组。
4. 购买 ECS，绑定固定公网地址或确认公网 IP 生命周期。
5. 准备 ECS 数据盘、快照和异地备份位置。
6. 在 Docker Compose 中配置 PostgreSQL/Redis 容器和持久化目录。
7. 申请覆盖 `<APP_DOMAIN>` 的 SSL 证书，优先使用 DNS 验证。
8. 大陆地域提交 ICP 备案。
9. 备案等待期间完成 ECS、Docker、镜像和私有验收。
10. 备案通过且站点合规项补齐后再切正式 DNS。

## 7. ICP 备案流程边界

大陆节点正式提供网站访问时，通常要完成 ICP 备案。大致步骤是：

```text
域名实名认证
  -> 准备符合备案条件的大陆云资源
  -> 阿里云备案平台填写主体、负责人、域名和网站信息
  -> 真实性核验
  -> 阿里云初审
  -> 管局审核
  -> 获得备案号
  -> 网站页脚展示备案号并链接工信部备案系统
```

材料、网站名称、前置审批和审核时间随主体、地域和业务变化。以阿里云备案平台和当地管局
要求为准，不在本文记录固定天数。

网站正式开通后，还要按所在地和业务要求办理公安联网备案，并展示对应编号和链接。备案号
不是只保存在控制台：页面展示也是上线验收的一部分。

## 8. 当前代码的合规检查

正式开放前至少人工检查：

| 检查 | 当前状态 |
|---|---|
| ICP/公安备案号展示 | `layout.html` 页脚已展示 ICP 备案号并链接工信部备案系统；公安联网备案编号取得后仍需按要求补充 |
| 隐私政策 | 当前没有独立页面，需要结合实际收集信息评估并补齐 |
| 用户协议/评论规则 | 当前没有独立页面，开放注册和评论前应评估 |
| 用户注销 | 当前已有用户删除流程，但还应验证入口和数据处理说明 |
| 上传和评论内容治理 | 有基础权限/限流，不等于完成内容合规和投诉处理机制 |

这部分涉及法律和平台规则时，应由实际运营主体根据业务获得合规意见，技术文档不能替代。

## 9. 建立非敏感资源台账

记录以下信息，供后续部署和故障定位使用：

```text
阿里云账号/资源所属主体：
地域：
VPC ID：
交换机 ID：
ECS 实例 ID、私网 IP、公网 IP：
PostgreSQL 数据目录与备份位置：
Redis 数据目录与备份位置：
正式域名：
证书到期日：
ICP/公安备案状态：
备份负责人：
告警联系人：
```

台账不保存密码、完整连接 URI、JWT Secret 或证书私钥。
