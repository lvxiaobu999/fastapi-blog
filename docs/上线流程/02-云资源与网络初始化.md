# 云资源与网络初始化

本章把已经购买的资源连成一条只走 VPC 内网的依赖链。目标不是先启动 FastAPI，而是先证明
ECS、RDS、Tair、磁盘和安全策略都处于正确边界。

## 1. 目标网络拓扑

```text
公网
  -> 安全组 80/443
  -> ECS Nginx

管理员固定 IP
  -> 安全组 22
  -> ECS SSH

ECS 私网 IP
  -> RDS PostgreSQL 5432（RDS 白名单/安全组）
  -> Tair Redis 6379 或实例指定端口（Tair 白名单）

禁止公网直接访问：8000、5432、6379
```

## 2. VPC 和交换机

示例规划：

```text
VPC:        10.10.0.0/16
应用交换机: 10.10.1.0/24
数据交换机: 10.10.2.0/24
```

这只是示例。实际网段不能与公司网络、VPN、其他已互联 VPC 冲突。第一次个人项目也可以使用
一个交换机，但仍要通过安全组和服务白名单限制方向。

检查：

- ECS、RDS、Tair 的控制台“网络类型”均为专有网络 VPC。
- 三者的 VPC ID 相同，而不是只看地域名称。
- 路由表没有不必要的公网或跨网段开放规则。
- 记录 ECS 私网 IP；RDS/Tair 白名单使用私网来源，不使用 ECS 公网 IP。

## 3. ECS 安全组

建议入方向：

| 协议/端口 | 来源 | 用途 |
|---|---|---|
| TCP 22 | `<ADMIN_IP>/32` | SSH 管理 |
| TCP 80 | `0.0.0.0/0`、按需 IPv6 | HTTP 跳转和证书/访问 |
| TCP 443 | `0.0.0.0/0`、按需 IPv6 | HTTPS |

不要添加：

```text
0.0.0.0/0 -> 8000
0.0.0.0/0 -> 5432
0.0.0.0/0 -> 6379
0.0.0.0/0 -> 22
```

备案或内测期间，可以先让 80/443 只允许管理员 IP，验收完成再按计划开放。

出方向如果采用默认放通，后续可以逐步收敛；至少要允许拉取系统包、基础镜像，并访问 RDS、
Tair、DNS 和时间同步服务。

## 4. ECS 操作系统基线

选择仍在安全支持期的 Alibaba Cloud Linux 或 Ubuntu LTS。初始化后先确认：

```bash
cat /etc/os-release
uname -a
date -u
timedatectl status
df -h
free -h
```

这些命令分别确认发行版、内核、UTC 时间、时间同步、磁盘和内存。JWT/TLS/日志都依赖准确
时间；磁盘不足会导致镜像构建和日志写入失败。

安全基线：

- SSH 使用密钥，不使用弱密码。
- 新建专用部署用户，日常不直接使用 root 登录。
- 修改 SSH 配置时保持第二个会话，验证新会话成功后再退出旧会话。
- 安装安全更新并安排重启窗口。
- 开启云安全中心、异常登录和漏洞告警。
- 不向应用容器挂载 Docker Socket。

Docker 安装放在 [04-ECS初始化与生产配置](./04-ECS初始化与生产配置.md) 执行。

## 5. 数据盘和 media 目录

当前头像和文章图片写到 `/app/app/media`。Compose 把宿主机目录挂载进去：

```text
/opt/fastapi-blog/data/media -> /app/app/media
```

如果购买独立数据盘：

1. 在控制台和 `lsblk -f` 确认哪块是全新数据盘。
2. 按阿里云数据盘文档分区、格式化和挂载。
3. 使用磁盘 UUID 写入 `/etc/fstab`，不要只依赖 `/dev/vdb` 等可能变化的设备名。
4. 重启一次确认自动挂载成功。
5. 再在挂载点下创建 `/opt/fastapi-blog/data/media`。

格式化会清空目标磁盘。本文不提供可以盲目粘贴的 `mkfs` 命令；必须先人工核对设备绝对路径和
数据状态。

如果先使用系统盘，也必须对 media 做独立备份。容器重建不会删除宿主目录，但 ECS/磁盘故障
仍会丢失文件。

## 6. 初始化 RDS PostgreSQL

建议在 RDS 控制台完成：

1. 选择与 ECS 相同 VPC。
2. 使用项目已测试或兼容的 PostgreSQL 版本；项目目标为 PostgreSQL 17，可售情况以控制台为准。
3. 创建业务数据库 `fastapi_blog`。
4. 创建独立应用账号，不把高权限管理账号放进 FastAPI。
5. 授予应用账号对业务数据库所需权限；Alembic 需要建表、索引、约束和修改结构权限。
6. 白名单只允许 ECS 私网 IP、应用交换机网段或受控安全组。
7. 使用 VPC 内网连接地址。
8. 开启自动备份、日志备份/PITR（实例支持时）、删除保护和存储告警。

不要在生产 RDS 中创建 `fastapi_blog_test` 后直接让日常测试连接。当前测试隔离仍需谨慎，完整
Pytest 应在本地或 CI 的一次性数据库执行。

### 6.1 数据库账号边界

至少区分：

```text
RDS 管理账号：创建数据库/账号、恢复、紧急维护
应用账号：FastAPI 和受控 Alembic 发布使用
只读账号：监控、报表或人工检查（可选）
```

应用连接串最终形状：

```text
postgresql+psycopg://<app_user>:<encoded_password>@<rds_private_host>:5432/fastapi_blog
```

密码中的 `@`、`:`、`/`、`#`、`%` 等必须做 URL 百分号编码。完整连接串只能进入 ECS 的受限
`app.env`，不能写入 Git。

## 7. 初始化 Tair/Redis

当前 `app/services/refresh_sessions.py` 使用：

- String、Set、TTL。
- `GET`、`SET`、`SADD`、`SREM`、`DEL`、`INCR`。
- Lua `EVAL` 和 `cjson`。
- Redis Cluster hash tag `{auth-user-<id>}`。

采购和初始化时要确认实例/账号支持这些能力。配置步骤：

1. 选择与 ECS 相同 VPC。
2. 创建独立账号和高强度密码，不允许匿名公网访问。
3. 白名单只允许 ECS 私网来源。
4. 记录内网 Host 和端口。
5. 设置内存、连接数、延迟、拒绝连接、淘汰和实例可用性告警。
6. 根据实例能力和合规要求决定 `redis://` 还是 `rediss://`。
7. 不与开发/测试共用 Key 前缀。

生产 URL 形状：

```text
redis://<user>:<encoded_password>@<tair_private_host>:6379/0
```

如果阿里云实例使用不同账号语法、端口或 TLS 参数，以实例控制台连接说明为准。不要通过反复
尝试并把完整错误粘贴到公开渠道排错。

## 8. 内网连通性检查

先只测 TCP，不输出密码：

```bash
nc -vz <RDS_PRIVATE_HOST> 5432
nc -vz <TAIR_PRIVATE_HOST> 6379
```

`nc` 是 netcat 客户端，部分最小化系统默认没有安装。Ubuntu 可以安装 `netcat-openbsd`；其他
发行版使用对应官方软件仓库的软件包。安装工具不等于开放端口，真正访问边界仍由 VPC、白名单
和安全组决定。

预期是连接成功。失败按顺序检查：

```text
Host/端口是否抄错
  -> ECS/RDS/Tair 是否同 VPC
  -> 交换机/路由是否互通
  -> RDS/Tair 白名单是否包含 ECS 私网来源
  -> ECS 出方向规则和系统防火墙
  -> 实例是否运行、是否要求 TLS/特殊账号格式
```

TCP 成功只证明网络和端口通，不证明数据库名、账号、密码、SSL 或应用驱动正确。真实协议连接
将在生产配置注入后由 Alembic 和 `/health/ready` 验证。

## 9. 备份和告警先于数据

在写入第一条生产数据前完成：

- RDS 自动备份策略、保留期、日志备份和手工备份入口。
- ECS/数据盘快照策略。
- media 到 OSS 或独立位置的周期备份设计。
- ECS CPU、内存、磁盘、实例状态和公网流量告警。
- RDS CPU、连接数、慢 SQL、磁盘、备份失败告警。
- Tair 内存、连接、延迟、拒绝连接、淘汰和可用性告警。
- 域名、证书、ECS、RDS、Tair 到期提醒。

备份任务显示“成功”还不够，上线后要安排隔离环境恢复演练。

- [ ] RDS/Tair 仅允许 ECS 私网来源。
- [ ] ECS 到 RDS/Tair 的 TCP 检查成功。
- [ ] `media` 目标磁盘/目录和快照策略已确定。
