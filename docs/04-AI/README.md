## 先建立三个正确认识

- AI 应用开发不等于训练大模型。多数业务项目的核心是模型 API、业务数据检索、工具调用、工作流、评测和工程治理。
- “回答得像真的”不等于“回答正确”。涉及博客文章、价格、订单、制度等事实时，答案必须来自数据库、搜索或其他可追踪工具，并附引用。
- Agent 不是越自主越好。步骤固定、风险高的业务优先使用确定性工作流；只有路径确实需要动态决策时才使用 Agent 循环。

## 本项目建议的第一个 AI 功能

实现“博客知识助手”：用户询问“帮我梳理博客中关于 Vue 的文章”，系统检索已发布文章，返回准确标题、链接、摘要和引用；若用户继续问某篇文章的内容，再基于对应正文生成带出处的总结。第一版不需要长期记忆，也不需要复杂多 Agent。

推荐演进顺序：

```text
PostgreSQL 关键词检索
  -> 混合检索（全文检索 + Embedding）
  -> 带引用的 RAG 问答
  -> 对话内上下文与摘要
  -> 工具调用和确定性工作流
  -> 有边界的 Agent
```
