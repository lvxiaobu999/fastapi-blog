# 一条不发散的 AI 应用开发学习路线

这条路线只有一个主线项目：把当前博客逐步做成“有引用的博客知识助手”。每一阶段只引入完成当前目标所必需的概念；没有完成上一阶段的验收，不进入下一阶段，也不同时学习多个 Agent 框架。

## 总规则：一条主线、一个供应商、一个框架起步

- 前 1 至 4 阶段只选一家模型供应商，先直接调用官方 SDK，不使用 LangChain、LangGraph 等编排框架。
- 每阶段都必须提交代码、测试、评测数据和一页复盘；看完视频但没有产出不算完成。
- 先做确定性函数，再做模型调用；先做单轮 RAG，再做会话；先做工作流，最后才做 Agent。
- 课程资源只按下面的“本阶段资源”阅读。其他链接放到 [05-官方文档与优质资源.md](05-官方文档与优质资源.md) 作为查阅索引，不作为并行课程。

## 阶段 0：建立后端地基

**目标**：能够独立维护一个可靠的 FastAPI 功能。

**学习顺序**：先读本项目 `docs/开发流程.md`、`docs/Router入口与请求调用链详解.md`、`docs/Service职责与调用链详解.md`；再读 FastAPI Tutorial、Pydantic v2 Models、SQLAlchemy asyncio 官方文档；最后学习 pytest、SSE 和 Docker 的最小用法。

**项目任务**：为博客增加一个普通的“文章搜索”接口，走完整的 Router -> Schema -> Service -> AsyncSession 链路，支持分页、权限和测试。前端只做一个搜索页面。

**产出**：一个不依赖模型的 API、单元/接口测试、请求链图和错误处理说明。

**进入条件**：能解释事务边界、异步阻塞、401/403/404/422；能自己定位一次数据库异常。否则继续阶段 0。

## 阶段 1：第一次模型调用与 Prompt 契约

**目标**：理解模型“不确定”，并用代码把它约束成稳定接口。

**学习顺序**：DeepLearning.AI 的 `ChatGPT Prompt Engineering for Developers`；随后阅读所选供应商的文本生成、Structured Outputs、Streaming、Errors/Timeouts 文档；最后阅读本目录 [02-AI应用核心知识体系.md](02-AI应用核心知识体系.md) 的 Prompt 和模型 API 小节。

**项目任务**：增加单轮 `POST /api/ai/chat`。输入问题，模型只做意图分类和回答草稿；输出必须通过 Pydantic/JSON Schema。前端用 SSE 展示流式回答，支持取消、超时和重试。

**产出**：Prompt v1、结构化响应 Schema、模型 fake 测试、20 条分类/回答样例、token 和成本记录。

**进入条件**：模型不可用时接口仍有明确错误；不能靠字符串截取 JSON；能说明 temperature、token budget 和重试的影响。

## 阶段 2：先搜索，再生成

**目标**：做出第一个真实可用的“Vue 文章梳理”功能。

**学习顺序**：先读 PostgreSQL Full Text Search；再读 Embedding 基础（Pinecone Learning Center 对应章节）；然后读 pgvector；最后读 DeepLearning.AI 的 `Building and Evaluating Advanced RAG Applications`，只学习检索、引用和评测部分。

**项目任务**：先用 PostgreSQL 全文检索返回真实标题/URL，再加入 pgvector Embedding 和混合检索。答案只允许使用检索片段，并返回文章级/章节级引用。文章发布、更新、下架都要同步索引。

**产出**：知识摄取脚本、chunk 规则、索引表和 migration、混合检索 Service、30 至 50 条评测集、Recall@k 和引用正确率结果。

**进入条件**：对关键词、同义表达、无答案、下架文章都能正确处理；能区分“检索错”与“生成错”。达到此处即可开始投递初级 AI 应用开发岗位。

## 阶段 3：上下文、会话和工具

**目标**：让助手能连续对话，并安全完成低风险业务动作。

**学习顺序**：阅读供应商 Function/Tool Calling 文档；阅读本目录 [02-AI应用核心知识体系.md](02-AI应用核心知识体系.md) 的 Context、Memory 和 Tool 小节；再学习 Redis TTL/缓存和本项目现有 Redis 文档。此阶段暂不学习 ReAct 框架。

**项目任务**：实现 `search_posts`、`get_post`、`list_my_bookmarks` 三个只读工具；再实现需要登录和确认的 `bookmark_post`。保存会话消息，采用“最近 N 轮 + 摘要”，不做隐式长期画像；前端显示工具执行状态。

**产出**：工具 JSON Schema、参数二次校验、鉴权/幂等/审计测试、会话表设计、token 裁剪策略和失败恢复说明。

**进入条件**：能处理工具超时、重复调用、越权、模型返回非法参数和用户取消；能明确哪些数据在 PostgreSQL、Redis 和本次上下文中。

## 阶段 4：工作流优先，受控 Agent 入门

**目标**：知道什么时候写工作流，什么时候才让模型动态选择步骤。

**学习顺序**：阅读 Anthropic `Building effective agents`；观看 Hugging Face Agents Course 中工具、循环和安全章节；用原生 Python 实现一次有限 ReAct 循环；最后再用 LangGraph 重写，比较代码、状态和 trace 的差异。

**项目任务**：做一个“文章研究助手”：搜索 -> 获取文章 -> 对比 -> 生成报告是固定工作流；只有“是否需要继续搜索”交给 Agent。限制工具白名单、最大步数、总超时和费用，写操作必须人工确认。

**产出**：状态机/流程图、step 事件日志、checkpoint、注入攻击集、Agent 与工作流的对照复盘。

**进入条件**：能解释为何该步骤需要 Agent；一次失败可通过 trace 定位；不会把“思维链文本”当成审计依据。

## 阶段 5：评测、可观测和企业化

**目标**：把 Demo 变成可上线、可回归、可控成本的系统。

**学习顺序**：先读 OpenTelemetry；再读 OWASP Top 10 for LLM Applications；学习 Ragas 或 promptfoo 的评测工作流；最后阅读 Full Stack Deep Learning 的 LLM/生成式 AI 生产课程。

**项目任务**：加入模型路由和降级、限流和预算、租户/文档 ACL、异步索引队列、Prompt/模型版本、离线回归、灰度开关和安全告警。

**产出**：系统设计文档、威胁模型、SLO、成本表、trace 截图、回归报告和故障演练记录。

**进入条件**：能在白板上讲清数据流、信任边界、权限、失败模式、指标和取舍。达到这里可面试企业级 AI 应用、Agent 平台或 AI 后端岗位。

## 每周固定节奏

每周只安排一个主题：第一天读官方文档并写术语卡；第二至四天在博客完成一个垂直切片；第五天补失败测试和评测；第六天做前端体验与可观测性；第七天写复盘并决定是否进入下一阶段。每周结束必须有可运行提交，不能只留下笔记。

## 面试判断

阶段 2 的项目可以投初级岗位；阶段 3 至少能回答工具、权限、Memory 和成本问题；阶段 4 能回答 Agent 设计；阶段 5 才适合主攻大型企业岗位。面试前优先准备“一个失败案例如何定位和修复”，它比背框架名更能证明实战能力。
