# 代码评审与优化记录（2026-08-10）

## 1. 评审范围与方法

本次沿完整请求链检查 `Router -> Depends/Schema -> Service -> ORM/Redis -> PostgreSQL/SQLite`，
并覆盖模板、前端请求封装、WebSocket、Alembic、Nginx、Compose、配置和测试。重点检查：

- 未发布内容和用户隐私是否可能在 HTML 或公开 API 中泄露。
- Access/Refresh Token 的签发、轮换、撤销、并发和 Redis Cluster 行为。
- 数据库事务、Redis 与文件系统跨存储操作失败时是否产生部分提交。
- 点赞、收藏、浏览足迹和评论在并发请求下是否触发 500 或重复展示。
- 生产 Host、Secret、CSP、限流、健康检查和第三方静态资源是否可控。
- 数据迁移能否为新环境提供应用运行所需的基础数据。

评审只记录有代码、测试或配置证据的结论。未在真实 RDS/Tair/Nginx 环境执行的内容单独列为
残余风险，不以本地单元测试替代生产验证。

## 2. 已完成的高优先级修复

### 2.1 未发布文章编辑内容泄露

- 页面 `GET /posts/{post_id}/edit` 只返回空编辑器外壳，不再把草稿正文渲染进匿名可读 HTML。
- 新增管理员接口 `GET /api/posts/admin/{post_id}`，由 `AdminUser` 在服务端执行认证和授权。
- 编辑页通过 Bearer Token 加载内容，数据完成前禁用提交按钮。

结论：隐藏后台页面不是权限边界，草稿正文现在只从受保护 API 返回。

### 2.2 Refresh Session 并发、撤销与 Redis Cluster

- Refresh Token 改为 `v1.<user_id>.<session_id>.<secret>`；Redis 只保存 `secret` 的 SHA-256
  摘要，不保存可直接重放的 Cookie 内容。
- 一个设备使用稳定 `session_id`，轮换只更新同一个 Session Key。旧 Token 与退出并发时，
  退出仍可定位并撤销当前会话，不再遗留轮换后的新 Key。
- 用户级 `generation` 支持密码修改、删号时一次性使所有旧设备会话失效。
- 同一用户的 Session、索引和 generation Key 使用相同 `{auth-user-<id>}` hash tag；Lua 脚本
  只访问同一 Redis Cluster slot，兼容 Tair/Redis Cluster 的原子执行要求。
- 前端 JSON API 与图片上传的 Refresh 增加 single-flight，共享同一次刷新请求，避免多个并发
  401 互相轮换并误清会话；上传在刷新成功后使用新 Access Token 自动重试一次。

兼容性：旧格式 Refresh Token 会失效，部署后用户需要重新登录；Access Token 继续沿用 OAuth2
Bearer 契约。

### 2.3 账户高风险操作的跨存储顺序

- 修改密码先暂存新哈希，再撤销 Redis 全部会话，最后提交数据库；Redis 失败时数据库不提交。
- 管理员删号和用户自助删号先提升会话 generation，再删除数据库用户。
- 这不是分布式事务，但失败方向调整为“用户仍存在、会话已失效”，不会出现用户已删除却仍能
  通过 Refresh 恢复身份的状态。

### 2.4 登录账号枚举时序

- 账号不存在时也执行一次固定 Argon2 占位哈希校验。
- API 继续对“账号不存在”和“密码错误”返回相同 `401` 错误契约。

该措施缩小应用层时序差异；公网环境仍必须配合 Nginx/WAF 限流和登录监控。

## 3. 已完成的可靠性与生产安全优化

### 3.1 评论和互动并发

- 浏览足迹使用 SQLite/PostgreSQL 方言 upsert。
- 点赞和收藏使用 `INSERT ... ON CONFLICT DO NOTHING` 后按结果切换状态，避免并发唯一约束 500。
- WebSocket 广播并发发送，单连接发送超时为 2 秒，慢连接不阻塞整个房间。
- 每条评论写入前重新验证 Access Token、用户是否存在以及文章是否仍发布。
- 单 WebSocket 连接限制为 10 秒内最多 5 条评论消息，超限返回协议错误并关闭连接。
- 前端按评论 ID 去重，HTTP 历史和 WebSocket 广播不会重复插入同一评论。

### 3.2 浏览器与第三方资源

- Toast UI Editor 及代码高亮插件固定版本并改为站内静态资源，运行时不依赖第三方 CDN。
- 移除布局中的内联启动脚本，为 `script-src 'self'` CSP 提供条件。
- 应用与 Nginx 同时设置 CSP、`nosniff`、Referrer、点击劫持和 Permissions Policy 响应头。

### 3.3 配置、健康检查与代理

- 新增 `ALLOWED_HOSTS` 并启用 `TrustedHostMiddleware`；生产不允许 `*` 或测试 Host。
- 生产 `SECRET_KEY` 至少 32 个字符；`REDIS_KEY_PREFIX` 禁止 `{`、`}`，避免破坏 Cluster hash tag。
- 新增 `/health/live`（只检查进程）和 `/health/ready`（检查数据库与 Redis）。
- Compose 健康检查改用 readiness，并从 `ALLOWED_HOSTS` 读取探测 Host。
- Nginx HTTP 跳转使用固定 `${APP_DOMAIN}`，不使用客户端可控 Host；普通请求与认证/注册接口
  使用不同速率的每 IP 限流，超限返回 `429`。

### 3.4 数据与文件生命周期

- 新增 `20260810_01` Alembic 数据迁移，幂等补充 `fastapi`、`python`、`other` 默认分类。
- 头像数据库提交失败时补偿删除新文件；提交成功后删除旧头像；删号后清理头像；路径异常或
  重复删除保持幂等。
- 迁移 downgrade 不删除分类业务数据，避免破坏已引用分类或运营人员修改后的记录。

## 4. 测试覆盖

新增或更新的关键回归路径包括：

- Refresh Token 轮换防重放、旧 Token 退出撤销当前会话、用户 generation 全量撤销。
- Redis 返回 bytes、Session TTL、摘要不包含 Cookie 原文、同用户 Key 使用相同 hash tag。
- 不存在账号仍执行密码哈希校验。
- WebSocket 每条消息复核上下文、评论速率限制和测试 Session 刷新参数。
- 生产短 Secret、通配 Host、Redis hash tag 前缀校验。
- liveness/readiness、安全响应头和非法 Host 拒绝。
- 替换头像后旧文件清理。

最终验证命令和结果以本文第 6 节及 `docs/开发流程.md` 的本次记录为准。

## 5. 残余风险与后续建议

以下项目没有在本轮被描述为“已解决”：

1. **Access JWT 即时撤销**：改密或删号后，现有 Access Token 最长仍可使用到 `exp`；当前每个
   受保护请求会查用户，删号会立即失败，但改密不会让 Access Token 立刻失效。需要强制即时
   失效时，可增加用户 token version 或短期 JTI denylist，并评估每请求 Redis/数据库成本。
2. **文章正文图片孤儿文件**：编辑器上传发生在文章提交前，用户放弃编辑会留下未引用图片。
   建议增加“扫描正文引用并清理超龄文件”的管理命令，迁移到 OSS 后使用临时对象与生命周期规则。
3. **WebSocket 多实例**：房间仍在单进程内存中，多 worker/多容器不会互相广播。扩容前接入
   Redis Pub/Sub、Streams 或专用消息系统，并处理断线重连和重复消息。
4. **限流是单 Nginx 实例状态**：多入口或 CDN 场景需在 SLB/WAF/API Gateway 统一限流；同时
   设计可信代理链，避免直接信任任意客户端提交的 `X-Forwarded-For`。
5. **历史分类迁移**：旧数据库若在 `145903a6328c` 前已有文章且没有可回填分类，仍可能在该
   非空外键迁移处失败。必须先备份并回填/清理历史数据；新增 head 迁移不能越过此前失败步骤。
6. **真实基础设施验证**：fakeredis 和 SQLite 不能替代 PostgreSQL 17、Tair Cluster、TLS 与
   Nginx 配置验收。上线前必须在隔离预发布环境执行迁移、并发 Refresh、429、CSP 和 WebSocket。
7. **测试依赖升级**：当前 Starlette 提示同步 `TestClient` 使用 httpx 的方式已弃用。待生态版本
   稳定后迁移到推荐测试客户端，避免未来依赖升级使 WebSocket 测试失效。
8. **第三方许可证**：站内分发 Toast UI 资源时应在发布制品中保留对应 MIT 许可证和版本清单。
