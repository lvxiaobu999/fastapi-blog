# 全项目代码审查报告（2026-09-13）

## 审查范围

覆盖 `app/`、`migrations/`、`tests/`、Docker/Nginx 配置和 `docs/` 入口。重点检查请求分层、异步一致性、认证授权、事务边界、输入输出契约、文件上传、WebSocket 生命周期、测试隔离和部署可复现性。

## 结论

当前项目已经形成可维护的单体后端：Router、Schema、Service、ORM、AsyncSession 和 Redis 的边界清楚，密码使用 Argon2，JWT 算法固定，Refresh Session 采用轮换和 Redis 原子脚本，WebSocket 有首条认证、消息限流和断开清理，测试使用内存 SQLite/fakeredis 隔离外部依赖。

本轮落地的低风险修复：

| 文件 | 改动 | 价值 |
| --- | --- | --- |
| `app/main.py` | 生命周期清理改为 `try/finally` | 取消或异常退出时仍释放 Redis/数据库连接池 |

| `app/services/comments.py` | 数据库回滚只捕获 `SQLAlchemyError` | 不把编程错误静默当成数据库错误 |

| `tests/test_pages.py` | 页脚断言改为当前主题变量 | 消除旧视觉实现留下的失效断言 |

## 分层审查

### Router 与 Schema

已经做到：端点声明 `response_model`；受保护修改先认证再授权；公开、本人、管理员响应分离；文章作者 ID 从 JWT 获取；分类和分页参数由 Schema/Query 校验；API 错误使用统一信封。

建议保持：新增接口继续避免把 ORM 对象直接作为公开契约；所有新增字段同步测试、`/docs` 和文档入口。

### Service 与事务

已经做到：Service 接收注入的 `AsyncSession`；写操作集中提交；唯一约束冲突回滚；互动使用数据库原子 upsert；评论提交成功后才广播；图片写盘失败和数据库失败有补偿删除。

建议补强：把重要写入统一封装为“提交失败回滚”的小辅助函数或明确的 `try/except SQLAlchemyError`，减少未来新增 Service 时漏写回滚的概率。

### 认证与授权

已经做到：JWT `sub/iat/exp` 必填且固定算法；登录失败不区分账号是否存在；Refresh Cookie 使用 HttpOnly/SameSite；生产配置拒绝非 Secure Cookie；管理员权限从数据库读取；密码变化撤销全部 Refresh Session。

需要产品决策：公开 `UserPublic` 当前包含 `is_admin`，`GET /api/users` 和文章作者嵌套响应会暴露角色标记。如果不需要公开展示角色，应拆出不含角色的 `UserPublic`，只在 `/api/auth/me` 和管理员接口返回 `is_admin`。

### 数据库与迁移

已经做到：Model 和 Alembic 共用同一 Base；外键级联/限制与 Service 检查配合；迁移链连续；生产配置限制 PostgreSQL 驱动。

需要优先统一：项目约定 PostgreSQL 17，但正式 Compose 和公网临时 Compose 使用 PostgreSQL 16；这是部署基线差异，应在一次有备份的升级窗口中决定并验证，不能只改镜像标签。

### 前端与内容安全

已经做到：CSP、Trusted Host、安全响应头、上传大小限制、图片魔数检查、随机文件名、前端请求取消和按钮 loading 状态。

建议补强：文章正文由 Toast UI 在浏览器渲染，正式运营前应明确 HTML/链接白名单或增加服务端 Markdown 清洗，并为上传图片增加尺寸/解压炸弹限制。当前只能依赖管理员账号和 CSP 降低风险。

## 性能与可扩展性建议

1. `posts.py` 的标题/正文搜索使用 `%keyword%` `ILIKE`，会随着文章量增长变成全表扫描；生产可迁移到 PostgreSQL `tsvector` + GIN，或先只做标题索引搜索。
2. 列表接口返回 `offset/limit` 数据但没有 total/next cursor；后台分页和大数据集建议加入统一分页元数据，且总数查询必须复用同一筛选条件。
3. `interaction_state()` 每次详情请求分别统计点赞和收藏；流量提升后可按文章聚合统计，或缓存短时间热点计数，但要保留关系表唯一约束。
4. `/media` 是本地目录，WebSocket 房间是单进程内存；当前单机部署合理，扩容前必须先迁移对象存储并增加跨实例广播。
5. Nginx 已有基本限流，但密码重置接口应单独纳入认证限流规则，邮件发送失败和重复请求还应观察指标。
