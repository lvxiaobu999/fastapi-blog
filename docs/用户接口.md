# 用户 CRUD 接口

用户注册、公开资料读取、本人资料维护和管理员管理使用不同的认证与响应边界。公开读取
只返回 `UserPublic`，不会包含邮箱；本人和管理员接口通过 Bearer Token 验证身份。

## 接口列表

| 方法 | 地址 | 成功状态 | 用途 |
| --- | --- | --- | --- |
| `POST` | `/api/users` | `201` | 创建用户 |
| `GET` | `/api/users` | `200` | 分页列出公开用户资料 |
| `GET` | `/api/users/{user_id}` | `200` | 获取单个公开用户资料 |
| `PATCH` | `/api/users/{user_id}` | `200` | 本人或管理员更新资料 |
| `DELETE` | `/api/users/{user_id}` | `200` | 本人或管理员删除用户 |

列表接口支持 `offset` 和 `limit`，其中 `limit` 的范围是 1 到 100。两个公开 GET 接口
使用 `UserPublic`，字段为 ID、用户名、昵称、头像和管理员标记，不返回邮箱。邮箱只出现在
注册结果、`/api/auth/me`、本人更新结果和管理员接口使用的 `UserResponse` 中。

## 创建用户

```json
{
  "username": "alice",
  "email": "alice@example.com",
  "password": "password123"
}
```

Service 会把用户名和邮箱规范化为小写，并使用 Argon2 哈希密码。响应不会包含 `password` 或 `hashed_password`。用户名或邮箱重复时返回 `409 Conflict`，请求字段不合法时返回 `422 Unprocessable Entity`。登录表单的 `username` 字段可以填写用户名或邮箱，匹配不区分大小写。

## 更新用户

更新接口需要 Bearer Token，且只允许本人或管理员操作。它使用 `PATCH`，只修改请求中
实际提供的字段：

```json
{
  "nickname": "Alice",
  "email": "alice@example.com"
}
```

普通资料接口只接受 `email` 和 `nickname`，额外字段会返回 `422`。密码和头像分别使用
专用接口，用户名与角色由管理员接口维护。公开 `/profile/{user_id}` 页面不会预渲染邮箱；
前端调用受保护的 `/api/auth/me` 确认当前用户就是页面本人后，才填充邮箱并显示编辑控件。

## 初始化数据库

首次使用接口前，在项目根目录执行：

```powershell
uv run alembic upgrade head
```

该命令读取当前环境的 `DATABASE_URL`。开发环境会迁移 SQLite，生产环境执行前必须确认 `ENV` 和 PostgreSQL 连接地址正确。

## 管理员分类管理

分类管理接口统一位于 `/api/admin/categories`，所有请求都必须携带管理员 Bearer Token。页面入口
是 `/admin/categories`；页面首次加载仍会先调用 `/api/auth/me`，只有 `is_admin=true` 才显示管理内容，
因此隐藏后台链接不是权限边界。

| 方法 | 地址 | 成功状态 | 用途 |
| --- | --- | --- | --- |
| `GET` | `/api/admin/categories` | `200` | 按 `sort_order`、ID 顺序列出全部分类 |
| `POST` | `/api/admin/categories` | `201` | 新增分类 |
| `PATCH` | `/api/admin/categories/{category_id}` | `200` | 部分更新分类 |
| `DELETE` | `/api/admin/categories/{category_id}` | `200` | 删除未被文章引用的分类 |

新增或更新请求示例：

```json
{
  "name": "数据库",
  "slug": "database",
  "sort_order": 10
}
```

`name` 长度为 1～50；`slug` 长度为 1～50，只允许小写字母、数字、连字符和下划线，例如
`python` 或 `web-development`。服务层会去掉名称和 slug 首尾空格并把 slug 转为小写；名称或
slug 重复返回 `409 Conflict`，字段格式错误返回 `422`。`sort_order` 越小越靠前，相同值按分类
ID 的稳定顺序排列。

删除分类前，服务端会检查 `post_categories` 关联表。如果任何文章仍引用该分类，返回 `409`：

```json
{
  "message": "Category is used by posts and cannot be deleted"
}
```

这项保护与数据库外键的 `ON DELETE RESTRICT` 相互配合，防止后台操作使文章变成无分类。需要删除
在用分类时，应先在文章管理或编辑页面把文章改到其他分类，再重试删除。
