# 个人博客最简上线流程（单机 Docker 版）

这份文档适用于当前阶段的低成本正式部署：一台 Linux ECS 通过 Docker Compose 运行
FastAPI、Nginx、PostgreSQL 和 Redis。不需要购买 RDS/Tair，但数据库、Redis、媒体文件和备份
都由你自己维护。

## 1. 最小架构和端口

```text
浏览器 -> DNS -> ECS Nginx（80/443） -> FastAPI app（Compose 内网 8000）
                                      |-> postgres（Compose 内网 5432）
                                      `-> redis（Compose 内网 6379）
```

| 服务 | Docker Compose 服务名 | ECS 公网端口 | 数据/配置 |
|---|---|---:|---|
| FastAPI | `app` | 不映射 | 镜像 + `/opt/fastapi-blog/data/media` |
| Nginx | `nginx` | 80、443 | `/opt/fastapi-blog/secrets/tls` 只读 |
| PostgreSQL 16 | `postgres` | 不映射 | `/opt/fastapi-blog/data/postgres` |
| Redis 7 | `redis` | 不映射 | `/opt/fastapi-blog/data/redis`（AOF）|

安全组只开放 22（限管理员 IP）、80、443。不要开放 5432、6379、8000；Compose 也不要写端口映射。
单机不是高可用：ECS 故障会同时影响应用和数据库，必须做异地备份和恢复演练。

## 2. 上线前本地检查

在项目根目录执行：

```powershell
$env:PYTHONPATH = (Get-Location).Path
uv run pytest -q
uv run ruff check .
```

确认测试数据库与业务库隔离，并提交一个已经测试的 Git tag/commit。服务器只部署该版本，不直接
在生产工作树修改源码。

## 3. ECS 初始化和代码

安装 Docker Engine 与 Compose 插件后确认：

```bash
docker --version
docker compose version
```

创建目录并同步代码：

```bash
sudo install -d -m 750 /opt/fastapi-blog/config
sudo install -d -o 70 -g 70 -m 700 /opt/fastapi-blog/data/postgres
sudo install -d -o 999 -g 1000 -m 700 /opt/fastapi-blog/data/redis
sudo install -d -o 10001 -g 10001 -m 750 /opt/fastapi-blog/data/media
sudo install -d -m 750 /opt/fastapi-blog/secrets/tls

cd /opt/fastapi-blog
git clone <仓库地址> current
cd current
git checkout <已测试的 Git tag 或 commit>
```

PostgreSQL/Redis 数据目录不应放在 `current` 代码目录，也不要把证书私钥、密码或 `.env` 提交到 Git。

## 4. 两个生产环境文件

### 4.1 `compose-prod.env`

仓库示例为 [`deploy/compose-prod.env.example`](../../../deploy/compose-prod.env.example)；本机真实文件
`deploy/compose-prod.env` 已加入忽略规则，不应提交。它由 `docker compose --env-file`
读取，负责 Compose 插值和四个容器的启动参数。现在其中包含数据库和 Redis 密码，因此必须上传到
`/opt/fastapi-blog/config/compose-prod.env` 并设置 `root:docker`、`chmod 640`（仅 root 执行 Compose 时可用 600）。

```bash
# 本地上传
scp deploy/compose-prod.env <ECS用户>@<ECS公网IP>:/tmp/compose-prod.env

# ECS 安装
sudo install -o root -g docker -m 640 /tmp/compose-prod.env \
  /opt/fastapi-blog/config/compose-prod.env
```

至少替换模板中的敏感占位符：

```dotenv
POSTGRES_USER=fastapi_blog
POSTGRES_DB=fastapi_blog_postgresql
POSTGRES_PASSWORD=<随机密码>
REDIS_PASSWORD=<随机密码>
PG_DATA_PATH=/opt/fastapi-blog/data/postgres
REDIS_DATA_PATH=/opt/fastapi-blog/data/redis
```

建议生成仅含字母、数字、点、`-`、`_` 的随机密码，避免 Compose 插值和 URI 编码错误。Compose 会
自动把同一密码注入 PostgreSQL 容器和 app 的连接串。PostgreSQL 数据目录已经初始化后，修改
`POSTGRES_PASSWORD` 不会自动修改数据库账号密码，必须执行 `ALTER ROLE`。

### 4.2 `app.env`

创建并保护 FastAPI 运行时配置：

```bash
sudo touch /opt/fastapi-blog/config/app.env
sudo chown root:root /opt/fastapi-blog/config/app.env
sudo chmod 640 /opt/fastapi-blog/config/app.env
sudoedit /opt/fastapi-blog/config/app.env
```

单机 Compose 方案的关键值如下；你的 JWT、邮件和 QQ 配置继续保留，但不要输出真实值：

```dotenv
ENV=production
PROJECT_TITLE=三碗博客
ALLOWED_HOSTS=["www.sanwan.xyz"]
PUBLIC_IP_MODE=false
AUTH_COOKIE_SECURE=true

# DATABASE_URL/REDIS_URL 由 compose.production.yaml 根据 compose-prod.env 自动注入；app.env 不再重复保存密码。
REDIS_KEY_PREFIX=fastapi-blog:production
REDIS_SOCKET_TIMEOUT_SECONDS=2

SECRET_KEY=<至少32个字符的随机值>
ACCESS_TOKEN_EXPIRE_MINUTES=30
REFRESH_TOKEN_EXPIRE_MINUTES=10080
REFRESH_IDLE_TIMEOUT_MINUTES=1440
LOG_LEVEL=INFO
LOG_FORMAT=json
LOG_TO_FILE=false
```

`APP_DOMAIN` 只放在 `compose-prod.env`，用于生成 Nginx 的 `server_name`；`ALLOWED_HOSTS` 放在
`app.env`，用于 FastAPI 的 Host 校验。不要同时保留 RDS/Tair 地址和 `postgres`/`redis` 地址；
每个变量只保留一个生效值。

## 5. 安装 HTTPS 证书

阿里云下载的 Nginx 证书安装为：

```bash
sudo install -o root -g root -m 644 www.sanwan.xyz.pem \
  /opt/fastapi-blog/secrets/tls/fullchain.pem
sudo install -o root -g root -m 640 www.sanwan.xyz.key \
  /opt/fastapi-blog/secrets/tls/privkey.key
```

Nginx 模板只读取 `fullchain.pem` 和 `privkey.key`。不要执行 `cat privkey.key`，不要把私钥提交 Git。

## 6. 首次构建、启动数据库/Redis、迁移和启动应用

在 ECS 的 `/opt/fastapi-blog/current` 执行：

```bash
cd /opt/fastapi-blog/current
export COMPOSE_FILE=compose.production.yaml
export COMPOSE_ENV=/opt/fastapi-blog/config/compose-prod.env
export APP_IMAGE_TAG=$(git rev-parse --short HEAD)
export COMPOSE_PROJECT_NAME=fastapi-blog-prod


# 自定义个dc的命令 dc等价于docker compose --env-file /opt/fastapi-blog/config/compose-prod.env -f compose.production.yaml
dc() {
  docker compose --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" "$@"
}

test -r "$COMPOSE_ENV"
test -r /opt/fastapi-blog/config/app.env
test -r /opt/fastapi-blog/secrets/tls/fullchain.pem
test -r /opt/fastapi-blog/secrets/tls/privkey.key
dc config -q
```


dc config -q 实际展开成 docker compose --env-file /opt/fastapi-blog/config/compose-prod.env -f compose.production.yaml config -q。



命令含义：`--env-file` 读取 Compose 参数；`-f` 指定生产 Compose；`APP_IMAGE_TAG` 固定镜像版本；
`config -q` 只检查 YAML 和变量展开，不启动容器。

先构建应用镜像，再启动 PostgreSQL 和 Redis：

```bash
dc build --pull app
dc up -d postgres redis
dc ps postgres redis
dc logs --tail=100 postgres redis
```

预期两个容器为 `healthy`。这一步会创建本机数据库/Redis 容器并初始化空数据目录；之后重启只会
复用已有目录，不会覆盖业务数据。

确认迁移链和当前版本：

```bash
dc run --rm app uv run --no-sync alembic heads
dc run --rm app uv run --no-sync alembic current
```

首次空库或代码有迁移时，先确认备份和目标目录，再执行一次：

```bash
dc run --rm app uv run --no-sync alembic upgrade head
```

最后启动 FastAPI 和 Nginx：

```bash
dc up -d app nginx
dc ps
dc logs --tail=100 app nginx
```

`app` 的 healthcheck 会执行 PostgreSQL `SELECT 1` 和 Redis `PING`；app 健康后 Nginx 才启动。正常的
`dc ps` 应看到四个服务：`app`、`nginx`、`postgres`、`redis`。

## 7. 首次验收

```bash
curl -fsS --resolve www.sanwan.xyz:443:127.0.0.1 \
  https://www.sanwan.xyz/health/ready
curl -fsSI https://www.sanwan.xyz/static/css/site.css
curl -fsSI https://www.sanwan.xyz/static/images/logo.png
curl -fsSI https://www.sanwan.xyz/static/images/favicon.ico
```

浏览器验证注册/登录、Refresh、退出、文章、分类、评论、上传和后台权限。不要使用 `curl -k` 忽略
证书错误。静态文件随 app 镜像发布，不要创建或挂载 `/opt/fastapi-blog/data/static`。

## 8. 日常发布

```bash
cd /opt/fastapi-blog/current
git fetch --all --prune
git checkout <已经测试的提交或标签>
export APP_IMAGE_TAG=$(git rev-parse --short HEAD)

dc config -q
dc build --pull app
# 有数据库迁移时，先备份，再执行
dc run --rm app uv run --no-sync alembic upgrade head
dc up -d --force-recreate app nginx
dc ps
```

每次 CSS、JavaScript、Logo 或 favicon 更新也必须 `build --pull app`，否则可能继续使用旧镜像。

## 9. 备份、恢复和危险操作

- PostgreSQL 数据目录 `/opt/fastapi-blog/data/postgres`：至少每日 `pg_dump`，并复制到 ECS 之外。
- Redis AOF 目录 `/opt/fastapi-blog/data/redis`：可备份，但它主要保存会话、验证码和 OAuth state，
  丢失后用户需要重新登录。
- `/opt/fastapi-blog/data/media`：必须与数据库一起备份，否则文章会出现断图。
- `app.env`、`compose-prod.env` 和 TLS 私钥：加密保存离线副本，不提交 Git。

示例（先确认空间和目标路径）：

```bash
mkdir -p /opt/fastapi-blog/backups
dc exec -T postgres sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB"' \
  | gzip > /opt/fastapi-blog/backups/fastapi_blog_$(date +%F).sql.gz
sudo tar -czf /opt/fastapi-blog/backups/media_$(date +%F).tar.gz \
  -C /opt/fastapi-blog/data media
```

执行备份命令时不要把密码写进命令行；使用容器内 `.pgpass`、临时受限环境变量或交互式输入。恢复
必须在隔离目录/数据库先演练，确认备份可读后再考虑生产恢复。

## 10. 安全和禁用操作

生产 ECS 安全组只开放 22、80、443，且 22 仅允许管理员 IP。禁止把 PostgreSQL、Redis 或 FastAPI
端口映射到公网。配置文件权限建议：

```bash
sudo chown root:docker /opt/fastapi-blog/config/*.env
sudo chmod 640 /opt/fastapi-blog/config/*.env
```

不要执行：

- `docker compose down -v`（会删除 Compose 卷；即使当前使用 bind mount 也容易误删其他资源）。
- `docker system prune -a --volumes`（会删除回滚镜像和卷）。
- 未备份、未审查的 `alembic downgrade`、`DROP DATABASE` 或手工删表。
- 把 `DATABASE_URL`、Redis 密码、JWT Secret、邮箱授权码或私钥贴到日志和聊天。

## 11. 上线完成标准

- [ ] 安全组只有计划中的 22/80/443，5432/6379/8000 未对公网开放。
- [ ] `compose-prod.env` 和 `app.env` 已安装且权限为 640 root:docker（或仅 root 读取的 600），真实值未进入 Git。
- [ ] `DATABASE_URL` 指向 `postgres:5432`，`REDIS_URL` 指向 `redis:6379`，账号/密码/数据库名一致。
- [ ] `dc ps` 中四个服务正常，`/health/ready` 返回 `{"status":"ready"}`。
- [ ] HTTPS、静态文件、登录、文章、分类、评论和上传均已验收。
- [ ] PostgreSQL、Redis、media 和配置文件均已有异地备份。

如果以后预算允许再迁移到 RDS/Tair，应先停止本机依赖并完成数据迁移，再改 `app.env` 地址；不要让
两套数据库同时接收流量。
