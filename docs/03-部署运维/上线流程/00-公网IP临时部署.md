# 备案和 TLS 证书完成前的公网 IP 临时部署

> 本文是备案/证书完成前的历史临时验收流程，不是当前正式上线流程。当前正式环境请使用四容器
> `compose.production.yaml`。若临时模式也要在 ECS 本机运行 PostgreSQL/Redis，应同时叠加
> `compose.public-ip.local-services.yaml`；本文中 `<RDS_PRIVATE_HOST>` 等托管地址仅保留作历史示例，
> 不需要为当前方案购买 RDS/Tair。

本文针对“域名仍在备案、TLS 证书还没有签发，但需要先在自己的 ECS/EIP 上验收博客”的阶段。
目标是让浏览器通过 `http://<ECS_PUBLIC_IP>` 访问当前 FastAPI 应用；它不是正式上线方案，
也不会把 HTTP 伪装成 HTTPS。

## 1. 先看结论

当前正式部署文件 `compose.production.yaml` 默认要求：

- Nginx 同时监听 80/443；
- `/opt/fastapi-blog/secrets/tls/fullchain.pem` 和 `privkey.key` 已存在；
- `ENV=production` 时 `AUTH_COOKIE_SECURE=true`。

因此不能只把域名替换成公网 IP。没有证书时直接启动正式 Compose 会因 Nginx 找不到证书
而失败；强行把 Cookie 改成非 Secure 又会被 Settings 拒绝。仓库现在提供一个显式的临时
`PUBLIC_IP_MODE`，并配套 HTTP-only Compose/Nginx 配置：

```text
浏览器 http://ECS_PUBLIC_IP
        |
        v
Nginx 容器（仅 80，限流、WebSocket Upgrade）
        |
FastAPI 容器（Compose 内网 8000）
        |-- PostgreSQL（内网）
        |-- Redis（内网）
        `-- ECS 持久化 media 目录
```

此模式会使用非 Secure 的 Refresh Cookie，登录续期才能在 HTTP 下工作；代价是登录 Cookie、
表单和请求内容都可能被窃听或篡改。备案和证书完成后必须切回 HTTPS，并立即轮换生产密钥或
撤销在 HTTP 阶段产生的会话。

## 2. 适用边界和安全警告

1. 只把它用于自己的验收、联调或受控内测。备案未完成前是否允许对公众提供网站，受云厂商、
   地域和监管要求影响，应以云厂商和相关主管部门要求为准。
2. 安全组优先把 TCP 80 来源限制为你的固定公网 IP；SSH 22 也只允许管理员 IP。不要为了
   “方便访问”开放 `0.0.0.0/0`，尤其不要开放 5432、6379 或 8000。
3. 不要在这个地址输入真实生产密码、管理密钥或其他高敏感信息。HTTP 明文不是证书问题，
   它本身就不能抵御中间人攻击。
4. 必须使用固定 EIP 或其他不会频繁变化的公网 IPv4。当前开关暂不支持 IPv6；不要把域名、
   `http://`、端口或路径写入 `ALLOWED_HOSTS`。
5. 同一台机器上不能同时启动正式 HTTPS Compose 和本临时 Compose，否则两者都会争用 80
   端口。切换前先停止当前入口，再启动另一套。

## 3. 仓库中已经准备好的修改

| 文件 | 用途 |
|---|---|
| `app/core/config.py` | 增加 `PUBLIC_IP_MODE`；仅生产环境、IPv4 字面 Host、`AUTH_COOKIE_SECURE=false` 的组合允许启动 |
| `tests/test_config.py` | 覆盖公网 IP 模式成功、域名误用和 Secure Cookie 冲突 |
| `compose.public-ip.yaml` | 复用生产 app 配置，但 Nginx 只映射 80，不挂载 TLS 目录 |
| `nginx/public-ip.conf.template` | HTTP-only 反代、限流、安全响应头和 WebSocket Upgrade |

正式 HTTPS 相关的 `compose.production.yaml`、`nginx/default.conf.template` 不要为这次临时
部署改成 HTTP；它们仍是备案和证书完成后的正式入口。

## 4. 前置条件

- 已有一台 Linux ECS 和固定公网 IPv4（记为 `<ECS_PUBLIC_IP>`）。
- Docker Engine 与 Compose 插件可用。
- PostgreSQL 和 Redis 已创建，ECS 可通过内网访问，且白名单已放行 ECS 内网地址。
- 已有一个经过测试的 Git tag/commit。
- 已确认 PostgreSQL 目标数据库名称、Redis 实例和备份策略。不要因为临时 IP 部署就改用
  SQLite；生产 Settings 明确要求 PostgreSQL。

下列占位符不能原样执行：

```text
<ECS_PUBLIC_IP>       ECS/EIP 的公网 IPv4，例如 203.0.113.10
<RELEASE_TAG>         已测试的 Git tag 或 commit
<RDS_PRIVATE_HOST>    PostgreSQL 内网地址
<REDIS_PRIVATE_HOST>  Redis/Tair 内网地址
<ENCODED_PASSWORD>    URL 百分号编码后的密码
```

## 5. ECS 初始化和代码

部署用户、Docker 安装和目录权限可沿用 [04-ECS 初始化与生产配置](04-ECS初始化与生产配置.md)。
临时模式至少准备这些目录（容器应用使用 UID 10001 写入 media）：

```bash
sudo install -d -m 755 -o deploy -g deploy /opt/fastapi-blog/current
sudo install -d -m 750 -o root -g docker /opt/fastapi-blog/config
sudo install -d -m 755 -o 10001 -g 10001 /opt/fastapi-blog/data/media
```

拉取已测试版本；生产服务器不要直接编辑源码：

```bash
git clone <YOUR_REPOSITORY_URL> /opt/fastapi-blog/current
cd /opt/fastapi-blog/current
git fetch --tags --prune
git checkout <RELEASE_TAG>
git status --short
git rev-parse --short HEAD
```

## 6. 创建两个受限配置文件

### 6.1 app.env（含 Secret，不进入 Git）

```bash
sudo touch /opt/fastapi-blog/config/app.env
sudo chown root:docker /opt/fastapi-blog/config/app.env
sudo chmod 640 /opt/fastapi-blog/config/app.env
sudoedit /opt/fastapi-blog/config/app.env
```

内容结构如下；真实密码、完整 URI 和 Secret 只在服务器受限文件中填写：

```dotenv
# 仍使用生产数据库和生产校验；不要改为 development，否则会被要求使用 SQLite。
ENV=production
PROJECT_TITLE=三碗博客

# 只写公网 IPv4，不带协议、端口或路径。
ALLOWED_HOSTS=["<ECS_PUBLIC_IP>"]

# 备案前临时 HTTP 开关。它是有意的明文风险，证书就绪后必须删除或改为 false。
PUBLIC_IP_MODE=true
AUTH_COOKIE_SECURE=false

DATABASE_URL=postgresql+psycopg://<APP_USER>:<ENCODED_PASSWORD>@<RDS_PRIVATE_HOST>:5432/fastapi_blog
SECRET_KEY=<RANDOM_SECRET_AT_LEAST_32_CHARS>
ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=15
REFRESH_TOKEN_EXPIRE_MINUTES=10080
REFRESH_IDLE_TIMEOUT_MINUTES=1440

REDIS_URL=redis://<REDIS_USER>:<ENCODED_PASSWORD>@<REDIS_PRIVATE_HOST>:6379/0
REDIS_KEY_PREFIX=fastapi-blog:public-ip
REDIS_SOCKET_TIMEOUT_SECONDS=2

LOG_LEVEL=INFO
LOG_FORMAT=json
LOG_TO_FILE=false
```

生成 Secret 时只在服务器终端输出并直接写入受限文件；不要复制到聊天、工单、命令脚本或日志：

```bash
python3 -c 'import secrets; print(secrets.token_urlsafe(64))'
sudo stat -c '%a %U %G %n' /opt/fastapi-blog/config/app.env
```

预期权限类似 `640 root docker`。密码中包含 `@`、`:`、`/` 或 `#` 时必须先 URL 编码。

### 6.2 compose-public-ip.env（不含 Secret）

```bash
sudoedit /opt/fastapi-blog/config/compose-public-ip.env
```

```dotenv
APP_PUBLIC_IP=<ECS_PUBLIC_IP>
APP_IMAGE_TAG=<RELEASE_TAG_OR_COMMIT>
APP_ENV_FILE=/opt/fastapi-blog/config/app.env
MEDIA_HOST_PATH=/opt/fastapi-blog/data/media
```

限制为 `644 root root` 或更严格；该文件可以记录部署参数，但不要把 `DATABASE_URL`、
`REDIS_URL` 或 `SECRET_KEY` 放进来。

## 7. 预检、构建和迁移

以下命令均在同一个服务器 Shell 中执行：

```bash
cd /opt/fastapi-blog/current
export COMPOSE_FILE=compose.public-ip.yaml
export COMPOSE_ENV=/opt/fastapi-blog/config/compose-public-ip.env

docker compose --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" config -q
docker compose --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" build --pull app
```

先用一次性 app 容器验证 Settings（不会连接数据库或 Redis，也不会输出 Secret）：

```bash
docker compose --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" run --rm app \
  uv run --no-sync python -c "from app.core import get_settings; s=get_settings(); print(s.env, s.public_ip_mode, s.allowed_hosts)"
```

预期类似 `production True ['203.0.113.10']`。如果出现 `AUTH_COOKIE_SECURE`、IPv4 或
`PUBLIC_IP_MODE` 校验错误，先修复 `app.env`，不要通过改成 `ENV=development` 绕过。

确认目标数据库和备份后再迁移。首次部署执行一次，后续发布也应按同一流程执行待应用迁移：

```bash
docker compose --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" run --rm app uv run --no-sync alembic heads
docker compose --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" run --rm app uv run --no-sync alembic current
docker compose --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" run --rm app uv run --no-sync alembic upgrade head
docker compose --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" run --rm app uv run --no-sync alembic current
```

不要在生产库运行 Pytest、`create_all`、未审查的 `downgrade` 或 `stamp head`。

## 8. 启动 HTTP-only 入口

如果 80 端口已有正式 Nginx，先确认服务和数据后再停止它：

```bash
docker compose --env-file /opt/fastapi-blog/config/compose-prod.env -f compose.production.yaml ps
docker compose --env-file /opt/fastapi-blog/config/compose-prod.env -f compose.production.yaml stop nginx
```

启动临时入口：

```bash
docker compose --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" up -d
docker compose --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" ps
docker compose --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" logs --tail=100 app nginx
```

预期 `app` 为 `healthy`、`nginx` 为 `running`，且 Nginx 只监听宿主机 80。不要将 8000
映射到公网；Compose 中的 `expose` 只在 backend 网络可见。

## 9. 用公网 IP 验收

服务器本机或管理员电脑执行：

```bash
curl -fsS "http://<ECS_PUBLIC_IP>/health/live"
curl -fsS "http://<ECS_PUBLIC_IP>/health/ready"
curl -I "http://<ECS_PUBLIC_IP>/"
```

预期：

- `/health/live` 返回 `{"status":"ok"}`；
- `/health/ready` 返回 `{"status":"ready"}`；
- 首页返回 200，并带 `X-Request-ID`；
- 不会跳转 HTTPS，也不会尝试读取证书。

浏览器打开 `http://<ECS_PUBLIC_IP>/`，重点验证首页、注册/登录、文章发布、图片上传、退出
和评论 WebSocket。HTTP 页面使用 `ws://`，前端会根据当前页面协议自动选择，不需要开放额外
WebSocket 端口。登录后等待 Access Token 过期或手动触发受保护请求，确认 `/api/auth/refresh`
能正常续期；若 Refresh 失败，优先检查浏览器是否收到 `refresh_token` Cookie 以及 Redis
连接，而不是反复重启容器。

## 10. 日常查看和停止

```bash
docker compose --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" ps
docker compose --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" logs --tail=200 app nginx
docker compose --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" restart app
```

停止临时站点时只停止容器，不删除卷和 media：

```bash
docker compose --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" stop
```

不要执行 `docker compose down -v` 或 `docker system prune -a --volumes`；它们可能删除数据或
回滚镜像。

## 11. 切回正式域名 HTTPS

取得备案和证书后按以下顺序切换，避免把明文模式遗留在线上：

1. 在正式域名的 DNS 和证书准备好前，先保持 IP 站点仅限管理员来源。
2. 创建新的生产 `app.env`：
   - `ENV=production`；
   - `ALLOWED_HOSTS=["<APP_DOMAIN>"]`；
   - 删除或设置 `PUBLIC_IP_MODE=false`；
   - `AUTH_COOKIE_SECURE=true`；
   - 使用正式环境隔离的 `REDIS_KEY_PREFIX`；
   - 轮换 `SECRET_KEY`，使 HTTP 阶段签发的 Access JWT 失效。
3. 将 Nginx 的 `fullchain.pem` 和 `privkey.key` 放到正式文档规定的受限目录，检查域名 SAN
   和私钥权限。
4. 停止 `compose.public-ip.yaml`，再按 [04-ECS 初始化与生产配置](04-ECS初始化与生产配置.md)、
   [05-首次部署与数据库迁移](05-首次部署与数据库迁移.md) 和 [06-DNS、HTTPS 切流与上线验收](06-DNS-HTTPS切流与上线验收.md)
   启动 `compose.production.yaml`。
5. 验收 `https://<APP_DOMAIN>/health/live`、`/health/ready`、登录、刷新、上传和 `wss://`
   评论；确认公网 IP HTTP 入口已关闭或不再指向应用。

## 12. 故障对照

| 现象 | 先检查 |
|---|---|
| `nginx` 因证书失败 | 是否误用了 `compose.production.yaml`；公网 IP 模式不需要 TLS 挂载 |
| Settings 要求 Secure Cookie | `PUBLIC_IP_MODE=true`、`AUTH_COOKIE_SECURE=false`、`ENV=production` 是否同时存在 |
| Settings 拒绝 Host | `ALLOWED_HOSTS` 是否是 JSON 数组中的纯 IPv4，浏览器 URL 是否使用同一 IP |
| 502 Bad Gateway | `docker compose ps`、app health、RDS/Redis 白名单和容器日志 |
| readiness 503 | 数据库 `SELECT 1` 或 Redis `PING` 失败；查看底层异常，不要用重启循环掩盖 |
| 上传失败或重启后图片消失 | media 宿主目录是否由 UID 10001 写入并正确挂载 |
| 评论连接失败 | 浏览器是否使用 `ws://<IP>/api/posts/<id>/comments/ws`，Nginx Upgrade 头是否保留 |

本临时模式的终止条件是“域名、备案、证书和 HTTPS 验收全部完成”，不是“IP 页面暂时能打开”。
