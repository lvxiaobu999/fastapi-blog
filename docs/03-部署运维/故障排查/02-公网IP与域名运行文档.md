# 公网 IP 与备案后域名运行文档

> 当前正式环境已经改为 ECS 单机 Docker Compose，`compose.production.yaml` 会同时创建 `app`、`nginx`、
> `postgres`、`redis` 四个服务。本文的 RDS/Tair 段落是历史网络示例；正式部署请使用
> `/opt/fastapi-blog/config/compose-prod.env`，不要按旧示例把连接串填写为 RDS/Tair 地址。

本文只回答一个选择问题：

| 当前条件 | 使用文件 | 访问方式 |
|---|---|---|
| 没有域名，或域名/证书还没准备好 | compose.public-ip.yaml + nginx/public-ip.conf.template | http://<ECS_PUBLIC_IP> |
| 无域名且 PostgreSQL/Redis 也运行在本机（历史临时入口） | compose.public-ip.yaml + compose.public-ip.local-services.yaml | app 连接 postgres、redis 服务名 |
| 域名备案通过、DNS A 记录已生效、TLS 证书已下载 | compose.production.yaml + nginx/default.conf.template | https://<APP_DOMAIN> |

同一台机器不能同时启动两种入口：两者都会占用 80，正式模式还会占用 443。切换前先停止
当前 Compose 项目；不要使用 down -v。

## 1. 先区分“外部服务”和“公网服务”

文档里说“外部 PostgreSQL/Redis”，指它们不在 FastAPI 的 app 容器或当前 Compose 文件中，
并不代表它们暴露在互联网。推荐的 RDS/Tair 部署通常是：

```text
浏览器 --公网--> ECS 公网 IP/EIP --Nginx--> FastAPI 容器
                         |
                         `-- VPC 私网 --> RDS PostgreSQL / Tair Redis
```

因此：

- ECS 的公网 IP 只给浏览器、管理员 SSH 和 Nginx 入口使用；
- ECS 的私有 IP 用于 VPC 内部通信、RDS/Tair 白名单和安全组规则；
- `DATABASE_URL` 应填写 RDS 的 VPC 内网地址，不应填写 ECS 公网 IP；
- `REDIS_URL` 应填写 Tair 的 VPC 内网地址，不应填写公网地址；
- 只有本机 Docker 依赖覆盖层才使用 `postgres`、`redis` 这两个 Compose 服务名；
- “RDS/Tair 在 ECS 外部”描述的是部署边界，“在公网”描述的是网络路径，两者不是同一个概念。

## 2. 两套配置的边界

### 无域名公网 IP 模式

- Nginx 只监听 80，不读取证书，不跳转 HTTPS。
- app 仍运行生产环境，数据库必须是 PostgreSQL，Redis 必须可用。
- PUBLIC_IP_MODE=true 只允许 IPv4 字面量作为 ALLOWED_HOSTS。
- AUTH_COOKIE_SECURE=false 是 HTTP 临时验收的必要例外；登录 Cookie 会明文传输。
- 只用于受控内测，不输入真实生产密码，不向公众开放。

### 备案后正式域名模式（当前使用）

- Nginx 监听 80/443，80 跳转 HTTPS。
- ALLOWED_HOSTS=["<APP_DOMAIN>"]，证书 SAN 必须包含同一域名。
- AUTH_COOKIE_SECURE=true，PUBLIC_IP_MODE=false 或不设置。
- PostgreSQL 和 Redis 由正式 Compose 本机创建；连接主机固定为 `postgres`、`redis`，密码仅放在 `compose-prod.env`。

## 3. 服务器目录和权限

以下目录只示例路径；不要把真实配置提交到 Git：

~~~bash
sudo install -d -m 750 -o root -g docker /opt/fastapi-blog/config
sudo install -d -m 755 -o 10001 -g 10001 /opt/fastapi-blog/data/media
sudo install -d -m 750 -o root -g docker /opt/fastapi-blog/secrets/tls
~~~

正式 HTTPS 还需要：

~~~text
/opt/fastapi-blog/secrets/tls/fullchain.pem
/opt/fastapi-blog/secrets/tls/privkey.key
~~~

私钥权限建议为 640 root:docker，不要用 cat 输出。

## 4. 无域名：公网 IP + RDS/Tair 私网 PostgreSQL/Redis（历史方案）

当前低成本方案无须购买 RDS/Tair；无域名内测应参考下一节的本机服务覆盖层，正式域名则直接使用第 6 节。

### 3.1 app.env

~~~bash
sudoedit /opt/fastapi-blog/config/app-ip.env
sudo chown root:docker /opt/fastapi-blog/config/app-ip.env
sudo chmod 640 /opt/fastapi-blog/config/app-ip.env
~~~

内容结构：

~~~dotenv
ENV=production
PROJECT_TITLE=三碗博客
ALLOWED_HOSTS=["<ECS_PUBLIC_IP>"]
PUBLIC_IP_MODE=true
AUTH_COOKIE_SECURE=false

DATABASE_URL=postgresql+psycopg://<APP_USER>:<ENCODED_PASSWORD>@<POSTGRES_PRIVATE_HOST>:5432/fastapi_blog
SECRET_KEY=<RANDOM_SECRET_AT_LEAST_32_CHARS>
ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=15
REFRESH_TOKEN_EXPIRE_MINUTES=10080
REFRESH_IDLE_TIMEOUT_MINUTES=1440

REDIS_URL=rediss://<REDIS_USER>:<ENCODED_PASSWORD>@<REDIS_PRIVATE_HOST>:6379/0
REDIS_KEY_PREFIX=fastapi-blog:public-ip
REDIS_SOCKET_TIMEOUT_SECONDS=2

LOG_LEVEL=INFO
LOG_FORMAT=json
LOG_TO_FILE=false
~~~

如果 Redis 没有 TLS，把 rediss:// 按服务商要求改为 redis://；不要把密码写在 Compose YAML。

### 3.2 Compose 参数文件

~~~bash
sudoedit /opt/fastapi-blog/config/compose-public-ip.env
sudo chmod 640 /opt/fastapi-blog/config/compose-public-ip.env
~~~

~~~dotenv
APP_PUBLIC_IP=<ECS_PUBLIC_IP>
APP_IMAGE_TAG=<RELEASE_TAG_OR_COMMIT>
APP_ENV_FILE=/opt/fastapi-blog/config/app-ip.env
MEDIA_HOST_PATH=/opt/fastapi-blog/data/media
~~~

### 3.3 预检、迁移、启动

~~~bash
cd /opt/fastapi-blog/current
export COMPOSE_ENV=/opt/fastapi-blog/config/compose-public-ip.env
export COMPOSE_FILE=compose.public-ip.yaml

docker compose -p fastapi-blog-ip --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" config -q
docker compose -p fastapi-blog-ip --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" build --pull app

docker compose -p fastapi-blog-ip --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" run --rm app uv run --no-sync alembic heads
docker compose -p fastapi-blog-ip --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" run --rm app uv run --no-sync alembic current
docker compose -p fastapi-blog-ip --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" run --rm app uv run --no-sync alembic upgrade head

docker compose -p fastapi-blog-ip --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" up -d
docker compose -p fastapi-blog-ip --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" ps
docker compose -p fastapi-blog-ip --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" logs --tail=100 app nginx
~~~

如果 app 镜像构建只有容器 DNS 失败、宿主机网络正常，可临时在同一个 Compose 参数文件加入：

~~~dotenv
UV_INDEX_URL=https://mirrors.aliyun.com/pypi/simple
~~~

然后重新 build。它只是包索引切换，不等于修复 Docker DNS；优先完成 README 中的 DNS 诊断。

### 3.4 IP 验收

~~~bash
curl -fsS "http://<ECS_PUBLIC_IP>/health/live"
curl -fsS "http://<ECS_PUBLIC_IP>/health/ready"
curl -I "http://<ECS_PUBLIC_IP>/"
~~~

预期 live/ready 为 200，首页为 200，HTTP 不跳转 HTTPS。安全组只开放受控来源的 80 和
管理员 SSH；不要开放 8000、5432、6379。

## 5. 无域名：本机 Docker PostgreSQL/Redis（临时验收方案）

只有确认你要在这台 ECS 自己维护数据库和 Redis 时才使用覆盖层。RDS/Tair 模式不要叠加它。

### 4.1 本机依赖的 app.env

DATABASE_URL 和 REDIS_URL 的主机必须是 Compose 服务名：

~~~dotenv
DATABASE_URL=postgresql+psycopg://<LOCAL_DB_USER>:<ENCODED_PASSWORD>@postgres:5432/<LOCAL_DB_NAME>
REDIS_URL=redis://:<ENCODED_REDIS_PASSWORD>@redis:6379/0
~~~

不要把 localhost 写给 app：在容器内它指向 app 容器自己，不是 PostgreSQL/Redis 容器。

### 4.2 Compose 参数文件

在受限文件中补充（不提交 Git）：

~~~dotenv
LOCAL_POSTGRES_USER=<LOCAL_DB_USER>
LOCAL_POSTGRES_PASSWORD=<LOCAL_DB_PASSWORD>
LOCAL_POSTGRES_DB=<LOCAL_DB_NAME>
LOCAL_REDIS_PASSWORD=<LOCAL_REDIS_PASSWORD>
PG_DATA_PATH=/opt/fastapi-blog/data/postgres
REDIS_DATA_PATH=/opt/fastapi-blog/data/redis
~~~

初始化目录并启动：

~~~bash
sudo install -d -m 700 /opt/fastapi-blog/data/postgres /opt/fastapi-blog/data/redis
cd /opt/fastapi-blog/current
export COMPOSE_ENV=/opt/fastapi-blog/config/compose-public-ip.env

docker compose -p fastapi-blog-ip --env-file "$COMPOSE_ENV" \
  -f compose.public-ip.yaml -f compose.public-ip.local-services.yaml config -q

docker compose -p fastapi-blog-ip --env-file "$COMPOSE_ENV" \
  -f compose.public-ip.yaml -f compose.public-ip.local-services.yaml up -d --build

docker compose -p fastapi-blog-ip --env-file "$COMPOSE_ENV" \
  -f compose.public-ip.yaml -f compose.public-ip.local-services.yaml ps
~~~

首次启动后，先确认 postgres、redis、app 都是 healthy，再执行：

~~~bash
docker compose -p fastapi-blog-ip --env-file "$COMPOSE_ENV" \
  -f compose.public-ip.yaml -f compose.public-ip.local-services.yaml run --rm app \
  uv run --no-sync alembic upgrade head
~~~

本机数据库的数据目录是持久数据，必须纳入备份；不要执行 down -v。

## 6. 备案和证书通过后：正式域名 HTTPS（当前流程）

### 5.1 必须先准备

- DNS A 记录：<APP_DOMAIN> -> <ECS_PUBLIC_IP>；
- 证书覆盖 <APP_DOMAIN>，文件名为 fullchain.pem 和 privkey.key；
- `compose-prod.env` 已上传并填写 PostgreSQL/Redis 密码，两个数据目录已备份；
- app-prod.env 中 PUBLIC_IP_MODE 已删除或为 false，AUTH_COOKIE_SECURE=true。

~~~dotenv
ENV=production
ALLOWED_HOSTS=["<APP_DOMAIN>"]
AUTH_COOKIE_SECURE=true
# DATABASE_URL/REDIS_URL 不在 app.env 重复填写，由 Compose 根据 compose-prod.env 注入。
SECRET_KEY=<NEW_RANDOM_SECRET>
~~~

切换 HTTPS 时建议使用新 Secret，确保 HTTP 阶段签发的 Access JWT 不再有效；同时按需要
撤销旧 Refresh Session。

### 5.2 启动正式 Compose

~~~bash
sudo install -m 644 fullchain.pem /opt/fastapi-blog/secrets/tls/fullchain.pem
sudo install -m 640 privkey.key /opt/fastapi-blog/secrets/tls/privkey.key
sudo chown root:docker /opt/fastapi-blog/secrets/tls/*.pem

cd /opt/fastapi-blog/current
export COMPOSE_FILE=compose.production.yaml
export APP_DOMAIN=www.sanwan.xyz
export APP_IMAGE_TAG=$(git rev-parse --short HEAD)
export APP_ENV_FILE=/opt/fastapi-blog/config/app.env
export MEDIA_HOST_PATH=/opt/fastapi-blog/data/media
export TLS_HOST_PATH=/opt/fastapi-blog/secrets/tls

docker compose -p fastapi-blog-ip --env-file /opt/fastapi-blog/config/compose-public-ip.env \
  -f compose.public-ip.yaml stop

export COMPOSE_ENV=/opt/fastapi-blog/config/compose-prod.env
docker compose -p fastapi-blog-prod --env-file "$COMPOSE_ENV" \
  -f "$COMPOSE_FILE" config -q
docker compose -p fastapi-blog-prod --env-file "$COMPOSE_ENV" \
  -f "$COMPOSE_FILE" build --pull app
docker compose -p fastapi-blog-prod --env-file "$COMPOSE_ENV" \
  -f "$COMPOSE_FILE" up -d postgres redis
docker compose -p fastapi-blog-prod --env-file "$COMPOSE_ENV" \
  -f "$COMPOSE_FILE" run --rm app uv run --no-sync alembic current
# 确认备份并审查迁移后才执行数据库写操作
docker compose -p fastapi-blog-prod --env-file "$COMPOSE_ENV" \
  -f "$COMPOSE_FILE" run --rm app uv run --no-sync alembic upgrade head
docker compose -p fastapi-blog-prod --env-file "$COMPOSE_ENV" \
  -f "$COMPOSE_FILE" up -d app nginx
docker compose -p fastapi-blog-prod --env-file "$COMPOSE_ENV" \
  -f "$COMPOSE_FILE" ps
~~~

### 5.3 HTTPS 验收

~~~bash
dig +short <APP_DOMAIN>
curl -I "http://<APP_DOMAIN>/"
curl -fsS "https://<APP_DOMAIN>/health/live"
curl -fsS "https://<APP_DOMAIN>/health/ready"
openssl s_client -connect <APP_DOMAIN>:443 -servername <APP_DOMAIN> </dev/null
~~~

预期 DNS 指向 EIP、HTTP 返回 301、HTTPS/live/ready 为 200、证书 SAN 匹配域名，登录和
Refresh Cookie 正常，评论 WebSocket 使用 wss://。

## 7. 常用排错命令（不泄露 Secret）

~~~bash
docker compose -p fastapi-blog-ip --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" ps
docker compose -p fastapi-blog-ip --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" logs --tail=200 app nginx

docker inspect --format '{{json .State.Health}}' \
  "$(docker compose -p fastapi-blog-ip --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" ps -q app)"

docker compose -p fastapi-blog-ip --env-file "$COMPOSE_ENV" -f "$COMPOSE_FILE" exec app \
  python -c "import json,os,urllib.request; h=json.loads(os.environ['ALLOWED_HOSTS'])[0]; r=urllib.request.Request('http://127.0.0.1:8000/health/ready',headers={'Host':h}); print(urllib.request.urlopen(r,timeout=3).read().decode())"

sudo ss -lntp | grep -E ':(80|443|8000|5432|6379)\b'
sudo systemctl status nginx --no-pager
~~~

docker inspect 只看 health 状态即可，不要全量输出环境变量。

## 8. 切换原则

- 无域名：使用 compose.public-ip.yaml；若数据库和 Redis 在本机，再叠加 local-services 文件。
- 域名备案和证书完成：使用 compose.production.yaml，不要继续运行公网 IP Compose。
- 不要把正式 nginx/default.conf.template 改成 HTTP；HTTP-only 模板是独立文件。
- 不要把 RDS/Tair 地址改成 postgres/redis，除非确实切到本机依赖覆盖层。
- 不要把密码、JWT Secret、Cookie、证书私钥写进 Compose YAML、Dockerfile、Git 或日志。
