# 开发与生产运行指令手册

> 当前正式环境是 ECS 单机 Docker Compose：`app`、`nginx`、`postgres`、`redis` 四个容器。
> RDS/Tair 相关文字只属于历史/未来迁移说明；生产连接串由 `compose-prod.env` 自动注入 `postgres` 和
> `redis` 服务名。请先阅读[Docker 本机 PostgreSQL 与 Redis 正式部署教程](08-Docker本机PostgreSQL与Redis正式部署.md)。

本文所有命令均在项目根目录执行。开发环境默认是 Windows PowerShell；生产环境默认是
阿里云 ECS Linux + Docker Compose。命令中的域名、路径和标签是占位符，不要复制真实密钥到
命令历史、日志、聊天或截图。

## 1. 命令安全等级

| 标记 | 含义 | 示例 |
| --- | --- | --- |
| 只读 | 不修改应用数据 | `git status`、`alembic current`、`docker compose ps` |
| 可恢复 | 会启动、停止或重建容器，但持久数据应保留 | `up -d`、`restart`、`down` |
| 写操作 | 会修改数据库或业务状态，执行前确认环境 | `alembic upgrade head`、`create-admin` |
| 破坏性 | 可能删除数据，本文不作为日常命令推荐 | `down -v`、`downgrade`、`pg_restore --clean` |

生产环境先执行只读检查，再执行写操作。看到 `downgrade`、`DROP`、`--clean`、`down -v`、
删除数据盘或覆盖备份时必须停止，确认目标、备份和恢复方案。

# 第一部分：开发环境（Windows PowerShell）

## 2. 首次准备

确认工具：

```powershell
python --version
uv --version
docker version
docker compose version
git --version
```

同步锁文件中的开发和运行依赖：

```powershell
uv sync --frozen
```

如果刚修改 `pyproject.toml`、需要重新计算锁文件：

```powershell
uv lock
uv sync
```

日常安装应优先使用 `uv add <package>` 或 `uv add --dev <package>`，让 `pyproject.toml` 与
`uv.lock` 同步变化，不要直接对 `.venv` 使用 `pip install`。

## 3. 开发环境变量

清除当前终端可能遗留的生产选择，让项目读取 `.env.development`：

```powershell
Remove-Item Env:ENV -ErrorAction SilentlyContinue
$env:ENV = "development"
```

查看非敏感配置是否加载正确：

```powershell
uv run python -c "from app.core import get_settings; s=get_settings(); print(s.env, s.project_title)"
```

不要使用 `Get-ChildItem Env:` 输出整个环境，也不要打印 `Settings`、`DATABASE_URL`、
`REDIS_URL` 或 `SECRET_KEY`。

## 4. 启动和管理开发 Redis

启动：

```powershell
docker compose -f compose.redis.development.yaml up -d
```

检查状态与 PING：

```powershell
docker compose -f compose.redis.development.yaml ps
docker compose -f compose.redis.development.yaml exec redis redis-cli ping
```

查看最近日志或持续跟踪：

```powershell
docker compose -f compose.redis.development.yaml logs --tail 100 redis
docker compose -f compose.redis.development.yaml logs -f redis
```

停止并保留容器/数据：

```powershell
docker compose -f compose.redis.development.yaml stop redis
```

恢复：

```powershell
docker compose -f compose.redis.development.yaml start redis
```

删除容器但保留命名卷：

```powershell
docker compose -f compose.redis.development.yaml down
```

禁止日常执行 `down -v`，它会删除 Redis Volume 和全部 Refresh Session。

## 5. 启动 FastAPI

自动重载的开发服务器：

```powershell
$env:ENV = "development"
uv run fastapi dev app/main.py
```

默认访问：

```text
网站：http://127.0.0.1:8000/
OpenAPI：http://127.0.0.1:8000/docs
```

模拟生产启动方式但仍读取开发配置：

```powershell
$env:ENV = "development"
uv run fastapi run app/main.py --host 127.0.0.1 --port 8000
```

停止前台服务器按 `Ctrl+C`。不要用结束所有 Python 进程的方式停止，它可能影响其他项目。

## 6. 测试

运行单个测试，最适合开发时快速反馈：

```powershell
uv run pytest tests/test_auth.py::test_rotated_refresh_token_cannot_be_replayed -vv -s
```

运行单个文件：

```powershell
uv run pytest tests/test_auth.py -vv
```

运行完整测试：

```powershell
uv run pytest -q
```

查看更完整输出：

```powershell
uv run pytest -vv
```

再运行完整测试；不得让测试连接需要保留数据的生产 PostgreSQL。

# 第二部分：生产环境（阿里云 ECS Linux）

生产 Compose 镜像在构建阶段已经完成依赖同步，因此生产容器内的命令统一写成
`uv run --no-sync`。这会直接使用镜像内的 `.venv`，避免 `uv` 在每次启动一次性容器时重新检查
或同步 `uv.lock`；新增依赖必须先提交锁文件并重新构建镜像。`run --rm` 会创建临时容器，
`exec` 进入已运行容器通常更快，但两者都必须加载 `/opt/fastapi-blog/config/compose-prod.env`。

## 12. 每次登录服务器后的准备

进入部署目录并确认版本：

```bash
cd /opt/fastapi-blog/current
git status --short
git rev-parse --short HEAD
docker version
docker compose version
```

设置当前终端的 Compose 参数：

```bash
export APP_DOMAIN=blog.example.com
export APP_IMAGE_TAG=$(git rev-parse --short HEAD)
export APP_ENV_FILE=/opt/fastapi-blog/config/app.env
export MEDIA_HOST_PATH=/opt/fastapi-blog/data/media
export TLS_HOST_PATH=/opt/fastapi-blog/secrets/tls
```

这些变量只负责告诉 Compose“使用哪个正式域名、哪个镜像版本以及宿主机上的哪些目录”。
其中：`APP_DOMAIN` 供 Nginx 生成 `server_name` 和 HTTPS 跳转；`APP_IMAGE_TAG` 标记已测试的
应用镜像；`APP_ENV_FILE` 指向注入 `app` 容器的生产配置；`MEDIA_HOST_PATH` 保存用户上传；
`TLS_HOST_PATH` 提供 Nginx 读取的 `fullchain.pem` 和 `privkey.key`。完整的逐项说明、错误示例
和检查方法见 [04-ECS 初始化与生产配置](../上线流程/04-ECS初始化与生产配置.md) 第 6 节。

变量只对当前 shell 和子进程有效，新开 SSH 会话必须重新设置。不要把包含 Secret 的应用配置
直接 `export` 到命令历史；数据库、Redis 和 JWT 配置应保存在权限受限的 `APP_ENV_FILE` 中。

## 13. 首次部署目录与权限

```bash
sudo install -d -o 10001 -g 10001 /opt/fastapi-blog/data/media
sudo install -d -m 750 /opt/fastapi-blog/config
sudo install -d -m 750 /opt/fastapi-blog/secrets/tls
sudo chmod 640 /opt/fastapi-blog/config/app.env
sudo chmod 640 /opt/fastapi-blog/secrets/tls/privkey.key
```

`app.env` 必须包含生产 `SECRET_KEY`、`AUTH_COOKIE_SECURE=true` 等应用配置；`DATABASE_URL`、`REDIS_URL`
由 Compose 根据 `compose-prod.env` 注入。证书目录必须包含 `fullchain.pem`、`privkey.key`。

## 15. 首次启动与迁移

先构建应用镜像：

```bash
docker compose --env-file /opt/fastapi-blog/config/compose-prod.env -f compose.production.yaml build --pull app
```

完成 PostgreSQL 逻辑备份并审查待执行迁移后，只运行一次：

```bash
docker compose --env-file /opt/fastapi-blog/config/compose-prod.env -f compose.production.yaml run --rm app uv run --no-sync alembic upgrade head
```

启动：

```bash
docker compose --env-file /opt/fastapi-blog/config/compose-prod.env -f compose.production.yaml up -d
docker compose --env-file /opt/fastapi-blog/config/compose-prod.env -f compose.production.yaml ps
docker compose --env-file /opt/fastapi-blog/config/compose-prod.env -f compose.production.yaml logs --tail=100 app nginx postgres redis
```

当前 Redis 迁移会删除旧数据库 `refresh_sessions` 表，使用户重新登录。不能用反复执行迁移来
排错；先读取最后一个数据库异常并确认目标 `postgres` 容器。


## 22. PostgreSQL、Redis 与媒体备份

PostgreSQL 使用 `pg_dump` 和数据目录/磁盘快照。执行迁移前记录备份任务完成状态，不要只
发起备份就立即迁移。Redis AOF 和 media 目录也要保存到 ECS 之外。

媒体目录只读查看：

```bash
sudo du -sh /opt/fastapi-blog/data/media
sudo find /opt/fastapi-blog/data/media -type f | wc -l
```

媒体备份应同步到 OSS 或独立备份目录，并配置版本/生命周期。不要用未核对目标的递归删除命令
清理 `/opt/fastapi-blog/data/media`。

## 25. 常见故障快速命令

### 502 Bad Gateway

```bash
docker compose --env-file /opt/fastapi-blog/config/compose-prod.env -f compose.production.yaml ps
docker compose --env-file /opt/fastapi-blog/config/compose-prod.env -f compose.production.yaml logs --tail=200 app nginx postgres redis
docker compose --env-file /opt/fastapi-blog/config/compose-prod.env -f compose.production.yaml exec nginx nginx -t
```

### 登录或 Refresh 返回 503

```bash
docker compose --env-file /opt/fastapi-blog/config/compose-prod.env -f compose.production.yaml logs --tail=200 app
docker compose --env-file /opt/fastapi-blog/config/compose-prod.env -f compose.production.yaml run --rm app \
  uv run --no-sync python -c "from app.core import get_settings; s=get_settings(); print(s.env, s.redis_url.get_secret_value().split('://', 1)[0])"
```

第二条只打印 Redis 协议，不打印地址、账号或密码。随后检查本机 `redis` 容器健康、AOF 目录、
内存和连接数。

### 数据库连接失败

```bash
docker compose --env-file /opt/fastapi-blog/config/compose-prod.env -f compose.production.yaml logs --tail=200 app postgres redis
docker compose --env-file /opt/fastapi-blog/config/compose-prod.env -f compose.production.yaml run --rm app uv run --no-sync alembic current
```

阅读最后一个 DBAPI 异常；检查 `postgres` 容器健康、数据目录、账号和数据库名称。

### WebSocket 无法连接

```bash
docker compose --env-file /opt/fastapi-blog/config/compose-prod.env -f compose.production.yaml exec nginx nginx -T
docker compose --env-file /opt/fastapi-blog/config/compose-prod.env -f compose.production.yaml logs --tail=200 nginx app postgres redis
```

确认 HTTPS 页面使用 `wss://`，Nginx 含 Upgrade/Connection Header，并且代理超时没有过短。

### 上传返回 413 或文件重启后丢失

```bash
docker compose --env-file /opt/fastapi-blog/config/compose-prod.env -f compose.production.yaml exec nginx nginx -T
docker compose --env-file /opt/fastapi-blog/config/compose-prod.env -f compose.production.yaml exec app sh -c 'id && ls -ld /app/app/media'
sudo ls -ld /opt/fastapi-blog/data/media
```

413 检查 `client_max_body_size 6m`；文件丢失检查挂载路径和 UID 10001 写权限。

## 26. 最常用命令速查

### 开发


## 27. 所有命令逐条说明

前面的章节按工作场景组织，本节用于逐条查询命令含义。表中的“影响”说明命令是否会改变环境：

- **只读**：查看信息，不修改业务数据。
- **本机配置**：只影响当前终端或本机开发环境。
- **服务状态**：启动、停止、重建或重新加载进程/容器。
- **代码/文件写入**：修改锁文件、格式或生成迁移文件。
- **数据库写入**：会修改数据库内容或结构，执行前必须确认环境。

| `docker image prune` | 交互删除没有标签且未使用的悬空镜像层。 | 镜像删除；先查看空间并保留回滚镜像。 |
| `docker builder prune` | 交互删除未使用的构建缓存。 | 构建缓存删除；下次构建可能变慢。 |
| `docker system prune -a --volumes` | 删除所有未使用镜像、网络、缓存并可能删除 Volume。 | **高风险破坏性命令，生产日常禁止执行。** |

### 27.10 故障排查专用命令

| 命令 | 具体作用 | 影响与预期结果 |
| --- | --- | --- |
| `docker compose ... run --rm app uv run --no-sync python -c "...redis_url..."` | 启动一次性 app 容器，只输出当前环境名和 Redis URL 协议，验证配置已注入且不泄露地址/密码。 | 只读；若 Settings 校验失败会直接报错。 |
| `docker compose ... exec app sh -c 'id && ls -ld /app/app/media'` | 查看容器运行用户 UID/GID 和容器内媒体目录权限。 | 只读；排查上传 Permission denied。 |
| `sudo ls -ld /opt/fastapi-blog/data/media` | 查看 ECS 宿主媒体目录 owner、group 和权限。 | 只读；应与容器 UID 10001 的写入需求一致。 |

故障章节会组合多条命令，因为一次错误通常跨越 Nginx、应用、PostgreSQL、Redis 和文件挂载。执行时仍按
表中的单条含义阅读：先状态和日志，再配置/连接检查，最后才考虑重启或写操作。
