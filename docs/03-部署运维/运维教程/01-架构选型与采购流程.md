# 架构选型与采购流程

> 当前已确定的正式方案是“单台 ECS + Docker Compose”：`app`、`nginx`、`postgres`、`redis` 四个服务均运行在 ECS 上。
> 本文把 RDS/Tair 保留为以后预算充足时的迁移选项，不把它们列为当前必购服务。实际部署请以[个人博客最简上线流程](../上线流程/个人博客最简上线流程.md)和[Docker 本机 PostgreSQL 与 Redis 正式部署教程](08-Docker本机PostgreSQL与Redis正式部署.md)为准。

## 1. 阿里云上的可选部署方式

| 方式 | 应用 | PostgreSQL | Redis | 适用场景 | 结论 |
| --- | --- | --- | --- | --- | --- |
| 轻量应用服务器 | Docker/进程 | 同机或外部 | 同机或外部 | 个人演示、预算极低 | 简单，但网络和扩展能力弱 |
| ECS + Docker Compose（当前） | Docker Compose | PostgreSQL 容器 | Redis 容器 | 个人博客、预算有限的正式站点 | **当前采用** |
| ECS + 托管中间件（可选） | Docker Compose | RDS | Tair | 需要托管备份和高可用 | 需额外购买，未来再评估 |
| ACK 托管 Kubernetes | Deployment | RDS | Tair | 多服务、多实例、团队运维 | 行业常见于中大型系统，当前过重 |
| 函数计算 FC | 函数/容器镜像 | RDS | Tair | 无状态、突发流量 | 当前有 WebSocket 和本地上传，改造后再考虑 |
| SAE | 托管应用/镜像 | RDS | Tair | 不想维护主机的容器应用 | 可选，成本和平台约束需评估 |

数据库和 Redis 放进 Docker 可以降低当前成本，但备份、磁盘扩容、补丁、监控和故障恢复都由自己负责。
如果以后迁移到 RDS/Tair，必须先完成数据迁移和回滚演练，再停掉本机依赖，不能只修改连接地址。

## 2. 当前项目为什么适合 Docker

建议使用 Docker，原因是依赖 Python 3.13、uv、系统运行环境可以固定，发布和回滚都以镜像
版本为单位。但容器化不会自动解决数据安全：

- PostgreSQL 和 Redis 使用 Compose 的 `postgres`、`redis` 服务，数据分别持久化到 ECS 数据目录；容器重建不会自动删除这些目录。
- `app/media` 必须挂载 ECS 数据盘目录，不能只存在容器可写层。
- `.env.production` 和密钥不得 COPY 进镜像。
- Alembic 是单独的发布步骤，不能让每个应用副本同时自动迁移。
- 当前 WebSocket 房间保存在进程内存；先保持单个应用进程。扩容到多个实例前，需要用
  Redis Pub/Sub 等实现跨实例广播。

## 3. 建议采购清单

### 必选

1. 域名：在阿里云域名购买，完成实名认证和备案（如适用）。
2. ECS：Linux，预留构建镜像、数据库和备份所需的磁盘空间。
3. 公网 IPv4/EIP：绑定 ECS；生产 DNS 不要指向临时 IP。
4. SSL 证书：可使用阿里云免费证书额度或其他可信 CA。
5. 独立数据盘或快照额度：用于 PostgreSQL、Redis、media 和备份。

### 推荐

- 云监控：ECS CPU、内存、磁盘、Docker 服务告警。
- SLS 日志服务：集中保存 JSON stdout 日志。
- OSS：多实例前用于头像和文章图片。
- ECS 数据盘与快照：当前 `/media` 的持久化和恢复。
- WAF、CDN、DDoS 防护：有公网业务、攻击风险或流量后按需启用。

## 4. 规格怎么起步

个人博客可从 2 vCPU、2～4 GiB ECS 起步；数据库和 Redis 选择可平滑升级的最低生产规格。
不要只按“能启动”采购，至少为构建镜像、系统更新、Nginx 和峰值请求留余量。具体价格和
可售规格会随地域、活动和日期变化，购买前以阿里云控制台为准。

地域选择原则：

- 中国大陆访问为主：选择目标用户附近的大陆地域，但必须备案。
- 不准备备案：选择中国香港或海外地域；大陆访问质量和延迟不保证。
- 若未来购买 RDS/Tair，再要求它们与 ECS 同地域、同 VPC、同可用区或低延迟可用区。

## 5. 网络拓扑与端口

- ECS 安全组公网入方向只开放 `22`、`80`、`443`。
- SSH 的 `22` 最好只允许管理员固定公网 IP；也可使用堡垒机/云助手。
- FastAPI 的 `8000` 不开放公网，只在 Docker 网络供 Nginx 访问。
- PostgreSQL `5432`、Redis `6379` 不开放公网。
- PostgreSQL `5432` 和 Redis `6379` 只加入 Compose `backend` 内部网络，不映射到 ECS 公网端口。
- 若未来改用 RDS/Tair，白名单只允许 ECS 私网来源，不要使用 `0.0.0.0/0`。

## 6. 采购顺序

1. 明确个人或企业主体、目标地域和预算。
2. 购买并实名认证域名。
3. 创建 VPC、交换机和安全组。
4. 购买 ECS 并准备独立数据盘、快照和异地备份位置。
5. 在 `deploy/compose-prod.env` 生成随机的 PostgreSQL/Redis 密码，上传到 ECS 后限制文件权限。
6. 配置 PostgreSQL 逻辑备份、Redis AOF 备份、media 备份和告警联系人。
7. 大陆节点提交 ICP 备案；网站开放后按要求完成公安联网备案。
8. 部署应用并通过 IP/临时 hosts 内测。
9. 配置 DNS 和 HTTPS，最后开放正式访问。

### 未来迁移到 RDS/Tair 时

1. 先为本机 PostgreSQL 做逻辑备份，并评估 Redis 会话、验证码和 OAuth state 的丢失影响。
2. 在 RDS/Tair 创建实例、账号、白名单、备份和监控策略。
3. 导入数据库并完成内网连通性、迁移版本和回滚验证。
4. 停止本机 `postgres`、`redis` 写入后，再把应用连接串切换到托管地址；确认稳定后再清理旧容器。
