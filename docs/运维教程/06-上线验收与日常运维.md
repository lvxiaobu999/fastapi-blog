# 上线验收与日常运维

> 当前正式环境是 ECS 单机 Docker Compose：`app`、`nginx`、`postgres`、`redis` 四个容器。
> 本文中如出现 RDS/Tair 字样，仅表示未来迁移时的检查项；当前不需要购买、配置或填写它们的地址。

本文命令默认已经在 `/opt/fastapi-blog/current` 定义以下包装函数；它确保每条 Compose 命令读取生产参数文件：

```bash
export COMPOSE_ENV=/opt/fastapi-blog/config/compose-prod.env
dc() { docker compose --env-file "$COMPOSE_ENV" -f compose.production.yaml "$@"; }
```

下文统一使用 `dc`，避免遗漏 `compose-prod.env` 导致服务名、密码或持久化目录解析错误。

## 1. 上线前检查表

### 云资源

- [ ] 域名实名认证完成；大陆节点 ICP 备案已通过。
- [ ] ECS 数据盘容量足够，Docker 服务开机自启，安全组仅开放 22（管理 IP）、80、443。
- [ ] PostgreSQL/Redis 未映射到宿主机公网端口，Compose `backend` 网络可正常解析 `postgres`、`redis`。
- [ ] `data/postgres`、`data/redis`、`data/media` 已配置异机/异地备份和恢复演练。
- [ ] ECS 数据盘、快照和 `/media` 备份策略已配置。

### 应用

- [ ] 已运行测试与 Ruff，发布的是明确 Git tag/commit。
- [ ] 镜像未包含 `.env*`、数据库文件、日志、上传文件或私钥。
- [ ] `ENV=production`、`AUTH_COOKIE_SECURE=true`，`ALLOWED_HOSTS` 为真实域名。
- [ ] `DATABASE_URL` 主机为 `postgres`、`REDIS_URL` 主机为 `redis`（由 Compose 自动注入），Key 前缀包含 production。
- [ ] 已备份本机 PostgreSQL（逻辑备份或数据目录快照），并审查 Alembic upgrade 内容。
- [ ] Compose 配置解析、容器健康检查和日志轮转正常。
- [ ] `/media` 是持久挂载，容器用户具有写权限。

### HTTP/HTTPS

- [ ] DNS 指向预期 EIP/SLB，HTTP 跳转 HTTPS。
- [ ] 证书域名匹配、链完整、到期告警已设置。
- [ ] Nginx `client_max_body_size` 支持 5 MB 上传但不过度放大。
- [ ] CSP、安全响应头和认证/注册接口 429 限流已验证。
- [ ] WebSocket 可以连接、认证、发送评论和收到广播。
- [ ] 80/443 可访问，8000/5432/6379 不可从公网访问。

## 2. 功能验收

使用专门的生产验收账号，至少验证：

1. 首页、文章列表和详情页正常。
2. 注册/登录，响应 Cookie 带 `Secure`、`HttpOnly` 和预期 `SameSite`。
3. Access Token 过期后 Refresh 能恢复会话；退出后旧 Refresh Token 不可重放。
4. 普通用户不能进入后台；管理员权限正常。
5. 上传头像和文章横图，重建 app 容器后文件仍存在。
6. WebSocket 在 `wss://` 下连接并能实时评论。
7. 创建、编辑、上下架文章以及 401/403/404 页面符合预期。
8. 日志存在 request_id，但没有密码、Cookie、JWT 或完整数据库/Redis URI。

## 3. 常用只读检查

```bash
dc ps
dc logs --tail=200 app nginx postgres redis
docker stats --no-stream
curl -I https://example.com/
curl -I http://example.com/
curl -fsS -H 'Host: example.com' http://127.0.0.1:8000/health/live
curl -fsS -H 'Host: example.com' http://127.0.0.1:8000/health/ready
```

数据库迁移状态：

```bash
dc run --rm app uv run --no-sync alembic current
dc run --rm app uv run --no-sync alembic heads
```

不要把含敏感 URI 的容器环境和异常详情复制到外部渠道。

## 4. 备份与恢复

- PostgreSQL：定期执行 `pg_dump`，并对 `data/postgres` 做文件级/磁盘快照；备份文件保存到 ECS 之外。
- `/media`：每日同步到 OSS 或独立备份空间，设置版本和生命周期策略。
- 配置：加密备份 Nginx、Compose 和 Secret；备份访问权限要比生产权限更严格。
- Redis：保留 AOF 目录并定期复制；Refresh Session、验证码和 OAuth state 丢失时会要求用户重新登录。

至少每季度做一次恢复演练：恢复到隔离环境，验证数据库迁移版本、图片和登录流程。只有“备份成功”
记录，没有恢复验证，不算可靠备份。

## 5. 监控告警

最低监控项：

- ECS：CPU、内存、磁盘使用率/IO、inode、网络、实例存活。
- 应用/Nginx：请求量、5xx、P95/P99 延迟、WebSocket 连接、容器重启次数。
- PostgreSQL：容器重启、连接数、慢 SQL、CPU、数据盘使用率、备份结果。
- Redis：容器重启、内存、延迟、拒绝连接、AOF 文件增长和数据盘使用率。
- TLS/域名：证书和域名到期时间。

将 `LOG_FORMAT=json` 的 stdout 接入 SLS 时，用 request_id 串联 Nginx 和应用日志；配置脱敏，
禁止采集 Authorization、Cookie、密码和完整 Token。

## 6. 故障定位顺序

```text
DNS/证书 -> 安全组/端口 -> Nginx -> app 容器 -> Settings
-> postgres/redis 健康状态 -> Alembic revision -> 最后一个 DBAPI/Redis 异常
```

- 502：先检查 app 健康和 Nginx 的 `proxy_pass` 服务名。
- 413：检查 Nginx `client_max_body_size`，不要无上限放开。
- 登录/刷新 503：检查 `redis` 容器健康状态、密码、AOF 目录权限和 `REDIS_URL`。
- 数据库 500：读取 Traceback 最后一个 DBAPI 异常，确认 `postgres` 健康状态、账号、数据库名和迁移。
- WebSocket 失败：检查 HTTPS 下是否使用 `wss://`，以及 Upgrade/Connection 头和代理超时。
- 图片重启后丢失：检查 `/app/app/media` 是否真的挂载到 ECS 数据盘。

## 7. 扩容前必须处理

当前版本适合单应用实例。扩容到多 worker、多容器或多 ECS 前：

1. 把图片迁到 OSS，数据库只保存对象 URL/Key。
2. 把 WebSocket 房间广播改为 Redis Pub/Sub 等跨实例通道。
3. 在前面增加 SLB，并配置健康检查和连接排空。
4. 确保迁移只由一个 release job 执行。
5. 验证多实例下 Refresh Session、后台操作和日志追踪。
6. 再评估 ECS Auto Scaling、SAE 或 ACK，而不是直接复制现有容器。
