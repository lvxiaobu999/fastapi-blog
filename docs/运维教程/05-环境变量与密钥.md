# 环境变量与密钥注入

## 1. 配置优先级

当前 `Settings` 优先级是：操作系统/容器环境变量 > `.env.production` > `.env` > 代码默认值。
单机生产使用两个受限文件：`compose-prod.env` 提供四个 Compose 服务的插值和数据库/Redis 启动密码，
`app.env` 由 `services.app.env_file` 注入 FastAPI。两个文件都不能提交 Git；建议 root:docker、权限 640（仅 root 执行 Compose 时可用 600）。

## 2. 生产变量模板

在 ECS 创建 `/opt/fastapi-blog/config/app.env`：

```dotenv
ENV=production
PROJECT_TITLE=三碗博客
ALLOWED_HOSTS=["www.sanwan.xyz"]

# `compose.production.yaml` 会根据 compose-prod.env 自动注入 `postgres:5432` 连接串，避免密码在两个文件重复。

# 至少 64 字节随机值；轮换会使现有 Access JWT 立即失效。
SECRET_KEY=<random_secret>
ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=15
REFRESH_TOKEN_EXPIRE_MINUTES=10080
REFRESH_IDLE_TIMEOUT_MINUTES=1440
AUTH_COOKIE_SECURE=true

# `compose.production.yaml` 会根据 compose-prod.env 自动注入 `redis:6379` 连接串。
REDIS_KEY_PREFIX=fastapi-blog:production
REDIS_SOCKET_TIMEOUT_SECONDS=2

LOG_LEVEL=INFO
LOG_FORMAT=json
LOG_TO_FILE=false
LOG_DIRECTORY=logs
LOG_MAX_BYTES=52428800
LOG_FILES_PER_DAY=5
LOG_RETENTION_DAYS=30
```

项目校验要求：生产数据库必须以 `postgresql+psycopg://` 开头；生产 Redis 不能指向
`localhost/127.0.0.1/::1`；Refresh idle 时间必须大于 Access Token 时间；`SECRET_KEY`
至少 32 个字符；`ALLOWED_HOSTS` 必须使用明确域名且不能为 `*`；Redis Key 前缀不能包含
`{` 或 `}`。Compose readiness 探测使用 `ALLOWED_HOSTS` 的第一个值作为 Host Header。

## 3. 生成和写入 Secret

在安全终端生成，不要把输出发到聊天或保存进 shell 脚本：

```bash
python3 -c 'import secrets; print(secrets.token_urlsafe(64))'
```

编辑完成后：

```bash
sudo chown root:docker /opt/fastapi-blog/config/app.env
sudo chmod 640 /opt/fastapi-blog/config/app.env
```

如果部署用户不属于 docker 组，应改成专用部署组。注意：能调用 Docker 的用户通常等同拥有
root 权限，不能只依赖文件权限保护 Secret。

## 4. 不要这样注入

- 不要在 Dockerfile 写 `ENV SECRET_KEY=...` 或 `ARG` 后写入镜像层。
- 不要提交 `.env.production` 的真实数据库/Redis地址和密钥。
- 不要把完整 URI 作为命令参数反复输入，命令历史和进程列表可能记录它。
- 不要通过前端 JavaScript、HTML 模板或 API 响应传递 Secret。
- 不要把 `docker inspect`、环境变量列表或完整异常截图公开。

## 5. 验证而不打印密钥

```bash
docker compose --env-file /opt/fastapi-blog/config/compose-prod.env -f compose.production.yaml run --rm app \
  uv run --no-sync python -c "from app.core import get_settings; s=get_settings(); print(s.env, s.project_title)"
```

这个命令只打印非敏感字段。应用启动成功只能证明格式校验通过；还要通过 Alembic、登录/刷新和
PostgreSQL/Redis 容器健康状态验证真实连接。

## 6. Secret 轮换影响

- `SECRET_KEY`：现有 Access JWT 全部失效。
- Redis 密码/地址：先同步 Redis 容器启动密码和 app.env，再重启 redis/app；切错会使登录/刷新返回 503。
- `REDIS_KEY_PREFIX`：旧 Refresh Session 不再可见，相当于全员重新登录。
- 数据库密码：已有数据目录时先在 PostgreSQL 执行 `ALTER ROLE`，同步两个环境文件，验证新连接后再重启应用。
- TLS 私钥：替换证书后 `nginx -t`，再 reload，不需要重启应用。
