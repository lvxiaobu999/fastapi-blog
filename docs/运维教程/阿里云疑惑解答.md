# 阿里云疑惑解答：公网 IP、私有 IP 与内网服务

本文解释部署博客时最容易混淆的概念：ECS 公网 IP、ECS 私有 IP、Docker Compose 服务名，以及
“本机 Docker 数据库”和“外部托管数据库”的区别。当前项目正式低成本方案使用 ECS Docker 的
`postgres`、`redis` 服务；文中 RDS/Tair 段落仅作为未来迁移参考。

## 1. 先记住一条结论

公网 IP 是给互联网用户访问网站的，私有 IP 是给云资源之间进行内网通信的。

~~~text
浏览器
  --互联网公网-->
ECS 公网 IP / EIP
  --> Nginx 80/443
  --> FastAPI 容器 8000

FastAPI 容器 --Compose backend 内网--> postgres 容器
FastAPI 容器 --Compose backend 内网--> redis 容器
postgres/redis 数据 --> ECS data/postgres、data/redis
~~~

因此：

- 浏览器访问网站使用 ECS 公网 IP 或域名；
- 当前 PostgreSQL 和 Redis 使用 Compose 服务名 `postgres`、`redis`；只有未来迁移托管服务时才使用 RDS/Tair 内网地址；
- 5432、6379、8000 不应该暴露到公网；
- ECS 私有 IP 不应该填到浏览器地址栏；
- ECS 公网 IP 也不应该作为 RDS/Tair 的数据库连接地址。

## 2. ECS 公网 IP 与私有 IP

### 2.1 公网 IP

公网 IP，也可能是绑定到 ECS 的 EIP，可以参与互联网通信。

主要用途：

- 浏览器访问博客；
- 管理员通过 SSH 登录 ECS；
- DNS A 记录指向服务器；
- Nginx 对外监听 80/443。

建议的安全组：

| 端口 | 用途 | 建议来源 |
|---|---|---|
| 22 | SSH 管理 | 只允许管理员固定公网 IP |
| 80 | HTTP 或临时公网 IP 模式 | 按需要开放，最好限制内测来源 |
| 443 | 正式 HTTPS | 按业务需要开放 |
| 8000 | FastAPI 内部端口 | 不开放公网 |
| 5432 | PostgreSQL | 不开放公网 |
| 6379 | Redis | 不开放公网 |

### 2.2 私有 IP

私有 IP 属于阿里云 VPC，只能在 VPC 内部或已配置互通的私网网络中访问。

主要用途：

- ECS 主机内部管理、SSH 安全组和网络排查；
- 如果未来购买 RDS/Tair，再用于 VPC 连接和白名单配置；
- 当前本机 PostgreSQL/Redis 使用 Docker `backend` 网络，不依赖 ECS 私有 IP。

查看 ECS 私有 IP：

~~~bash
ip addr
hostname -I
~~~

公网 IP 和私有 IP 不是同一个地址，也不能互相替代。

## 3. “外部 PostgreSQL/Redis”不等于“公网 PostgreSQL/Redis”（历史方案说明）

下面的 RDS/Tair 示例仅用于解释网络概念，当前正式部署不使用外部托管服务。

部署文档中说“外部 PostgreSQL/Redis”，通常只是指：

~~~text
PostgreSQL 和 Redis 不运行在 FastAPI 的 Docker Compose 里面
~~~

它不表示：

~~~text
PostgreSQL 和 Redis 暴露在互联网公网
~~~

例如：

~~~text
ECS：FastAPI + Nginx
RDS：PostgreSQL
Tair：Redis
~~~

RDS 和 Tair 虽然在 ECS 的 Compose 外部，但只要使用 VPC 内网地址，它们仍然是阿里云内网服务。

这里要区分两个维度：

| 说法 | 含义 |
|---|---|
| 外部服务 | 不在当前应用 Compose 中运行 |
| 公网服务 | 通过互联网公网地址访问 |
| 内网服务 | 通过 VPC 私有网络访问 |
| 托管服务 | 由阿里云负责运行、备份、监控或维护 |

推荐组合：

~~~text
FastAPI Compose
  --VPC 私网-->
RDS PostgreSQL
  --VPC 私网-->
Tair Redis
~~~

## 4. RDS/Tair 应该使用什么地址（仅未来迁移时）

如果使用阿里云 RDS PostgreSQL 和 Tair Redis，配置中的主机应填写控制台提供的 VPC 内网地址：

~~~dotenv
DATABASE_URL=postgresql+psycopg://<USER>:<ENCODED_PASSWORD>@<RDS_PRIVATE_HOST>:5432/<DATABASE>
REDIS_URL=redis://<USER>:<ENCODED_PASSWORD>@<TAIR_PRIVATE_HOST>:6379/0
~~~

不要填写：

- ECS 公网 IP；
- 浏览器访问博客的域名；
- ECS 的私有 IP，除非数据库确实安装在 ECS 主机上；
- RDS/Tair 的公网连接地址。

使用前确认：

1. ECS、RDS、Tair 位于同一 VPC，或已经配置网络互通；
2. RDS/Tair 白名单允许 ECS 私有 IP、私网网段或安全组；
3. 安全组允许 ECS 到目标的 5432/6379；
4. 数据库账号、密码、数据库名和 TLS 配置正确。

从 ECS 测试端口：

~~~bash
nc -vz <RDS_PRIVATE_HOST> 5432
nc -vz <TAIR_PRIVATE_HOST> 6379
~~~

结果解释：

| 结果 | 说明 |
|---|---|
| succeeded | 网络和端口基本可达，继续检查账号、密码和数据库名 |
| Connection refused | 主机可达，但服务未监听或主动拒绝 |
| timed out | 安全组、白名单、路由或网络 ACL 可能阻断 |
| Name or service not known | 主机名解析失败 |

## 5. 当前方案：数据库和 Redis 部署在 ECS Docker 上

如果选择在同一台 ECS 用 Docker 部署 PostgreSQL 和 Redis：

~~~text
FastAPI app 容器
  --> postgres 容器
  --> redis 容器
~~~

连接地址应该使用 Compose 服务名：

~~~dotenv
DATABASE_URL=postgresql+psycopg://<USER>:<ENCODED_PASSWORD>@postgres:5432/<DATABASE>
REDIS_URL=redis://:<ENCODED_PASSWORD>@redis:6379/0
~~~

不能写 localhost，因为在 app 容器中 localhost 指向 app 容器自己。

本项目中：

- `compose.production.yaml`：正式域名 HTTPS 入口，并直接创建四个服务；
- `compose.public-ip.yaml`：无域名时的临时 HTTP 入口，不能与正式入口同时启动；
- postgres：Compose 网络中的数据库服务名；
- redis：Compose 网络中的 Redis 服务名。

正式部署不要再叠加旧的 `compose.public-ip.local-services.yaml` 覆盖层，以免产生第二套数据库/Redis。

## 6. 公网 IP 模式与域名 HTTPS 模式

### 6.1 没有域名或证书时

使用：

~~~text
compose.public-ip.yaml
nginx/public-ip.conf.template
~~~

访问：

~~~text
http://<ECS_PUBLIC_IP>
~~~

配置重点：

~~~dotenv
ENV=production
ALLOWED_HOSTS=["<ECS_PUBLIC_IP>"]
PUBLIC_IP_MODE=true
AUTH_COOKIE_SECURE=false
~~~

这是临时 HTTP 验收模式。HTTP 会明文传输 Cookie、Token 和请求内容，不适合正式运营。

### 6.2 域名备案通过并取得证书后

使用：

~~~text
compose.production.yaml
nginx/default.conf.template
~~~

访问：

~~~text
https://<APP_DOMAIN>
~~~

配置重点：

~~~dotenv
ENV=production
ALLOWED_HOSTS=["<APP_DOMAIN>"]
PUBLIC_IP_MODE=false
AUTH_COOKIE_SECURE=true
~~~

还要准备：

~~~text
/opt/fastapi-blog/secrets/tls/fullchain.pem
/opt/fastapi-blog/secrets/tls/privkey.key
~~~

正式模式下，Nginx 监听 80/443，把 HTTP 跳转到 HTTPS，再将请求转发给 FastAPI。

## 7. 常见误区

### 误区一：数据库必须使用 ECS 私有 IP

不一定。

- 当前本机容器不使用 ECS 私有 IP，而使用 Compose 服务名；
- RDS/Tair 只有在未来迁移时才使用自己的 VPC 内网连接地址；
- ECS 私有 IP 主要用于 SSH 安全组、DNS 入口和未来 VPC 通信；
- 本机 Docker 数据库使用 Compose 的 `postgres`/`redis` 服务名。

### 误区二：没有域名就必须让数据库走公网

不需要。网站入口可以走公网 IP，而 FastAPI 到本机 `postgres`/`redis` 仍然走 Docker 私网：

~~~text
浏览器 -> ECS 公网 IP -> Nginx
FastAPI -> postgres/redis（Compose backend）
~~~

### 误区三：把私有 IP 写到浏览器地址栏

私有 IP 通常只能在 VPC 内访问，公网浏览器无法直接访问。浏览器应使用 ECS 公网 IP 或域名。

### 误区四：把 localhost 当作其他容器

容器内的 localhost 只代表当前容器。访问其他容器要用 Compose 服务名；当前 app 应使用 `postgres` 和 `redis`，不要使用 `localhost`。

### 误区五：RDS/Tair 在 Compose 外，所以就是公网

错误。Compose 外部描述的是部署边界，不是网络路径。

## 8. 最终判断表

| 实际情况 | DATABASE_URL 主机 | REDIS_URL 主机 | 入口 |
|---|---|---|---|
| ECS 本机 Docker PostgreSQL/Redis（当前） | postgres | redis | production；无域名时才用 public-ip |
| RDS + Tair 托管服务（未来） | RDS VPC 内网地址 | Tair VPC 内网地址 | public-ip 或 production |
| 公网数据库/Redis | 公网域名或公网 IP | 公网域名或公网 IP | 不推荐 |
| 本地开发 | SQLite 文件 | localhost 或本地 Redis | development |

合理的最终网络边界应该是：

~~~text
用户到 ECS：公网入口
ECS 到数据库/Redis：Compose backend 私网连接
数据库和 Redis：不暴露公网端口
FastAPI 8000：不暴露公网端口
~~~
