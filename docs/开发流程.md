# 开发流程与模块说明

本文记录项目当前已经实现的结构、关键文件用途和功能开发步骤。每次新增或调整功能时都应同步更新本文，避免代码已经变化而文档仍描述旧行为。

## 结构化日志与请求追踪

`app/core/logging.py` 统一配置文本/JSON 格式、stdout 或单一 UTC 日期文件输出，以及请求上下文。文件模式把所有达到 `LOG_LEVEL` 的事件按发生顺序写入 `logs/YYYY-MM-DD.log`，等级继续作为日志字段保留；同一天按单文件大小轮转，`LOG_FILES_PER_DAY` 与 `LOG_RETENTION_DAYS` 分别限制单日文件数和历史日期。`app/main.py` 的 HTTP 中间件生成 `request_id`，通过 `ContextVar` 让同一异步请求中的日志自动关联，并记录请求方法、路径、状态码和耗时；响应继续返回相同的 `X-Request-ID`。未知异常由 `app/exception_handlers.py` 记录完整服务端调用栈，但客户端响应不会泄露异常内容。

应用 Root Logger 可以在开发环境使用 DEBUG，但 `aiosqlite` 和 `sqlalchemy.engine` 被单独限制为 WARNING，避免数据库 cursor、execute、fetch 等底层日志淹没应用调试信息。

日志对象、Logger 名称层级、ContextVar 隔离、Token 清理、Filter 注入和完整输出顺序的逐步教学说明见 `docs/Python logging执行链路学习笔记.md`。

日志文件路径、环境变量覆盖、PowerShell 查看/清理、轮转验证和“为什么只改 LOG_LEVEL 不会生成文件”的操作说明见 `docs/Python日志文件操作.md`。

大型企业的 stdout JSON + 采集器 + 日志平台架构、与当前博客的规模差异，以及为什么博客采用“开发终端、单机日期文件、生产平台化”三层策略，见 `docs/企业日志管理与博客实践.md`。

生产环境默认向 stdout 输出 JSON，交给 Docker、Fluent Bit、Vector 或 Promtail 采集到 Loki/ELK；文件模式才由 `LOG_RETENTION_DAYS` 控制本地历史文件清理。本功能没有新增数据库表，不需要 Alembic Migration。详细配置、线上架构和排错方式见 `docs/Python日志管理与请求追踪.md`。

## 后台登录失效交互

后台与前台共用登录模态框，不再要求用户返回博客首页重新登录。后台打开时的认证链路如下：

```text
admin.js 请求 GET /api/auth/me
  -> Access Token 失效且 Refresh 失败
  -> api.js 清理本地 Token，并派发 blog:auth-required 事件
  -> auth.js 接收事件，在当前后台页面打开 loginModal
  -> 用户登录成功
  -> auth.js 刷新当前后台页面
  -> admin.js 重新校验登录用户是否为管理员
```

`admin.js` 的认证失败回调只负责隐藏后台受保护内容，不再额外显示“返回博客登录”的提示。这样登录入口只有一个，且新登录的是普通用户时，现有管理员校验仍会将其跳转到 `/forbidden`。

## 当前请求分层

```text
HTTP 请求
  → Router：解析参数、注入依赖、声明状态码、转换 HTTP 异常
  → Schema：校验请求并限制响应字段
  → Service：执行业务规则、查询、密码处理和事务提交
  → Model：描述 ORM 字段与数据库约束
  → Session / Engine：管理事务和数据库连接
  → SQLite（开发）或 PostgreSQL（生产）
```

Router 不直接编写 SQL，Service 不处理 HTTP 响应，Model 不负责请求参数校验。保持边界清晰可以让业务逻辑独立测试，也方便未来加入认证和权限控制。

用户名和邮箱在用户 Service 中统一去除首尾空格并转为小写保存。注册、资料更新和登录
查询使用 `func.lower()` 兼容历史混合大小写数据，因此 `Alice`、`ALICE` 和 `alice`
视为同一个用户名，邮箱同理。

## JWT 认证与 AJAX 表单

登录调用链为 `layout.html/login.html → auth.js → api.js → POST /api/auth/token → api_auth.py → services/auth.py → users 表`。成功后前端把短期 Token 保存到 `localStorage`。

发帖调用链为 `post_form.html → posts.js → api.js（Bearer Header）→ api_posts.py → dependencies/auth.py → services/posts.py → posts 表`。新增、修改和删除帖子仅允许管理员；用户资料修改和删除仅允许本人或管理员；新增帖子的 `user_id` 来自 JWT 对应数据库用户，不接受客户端指定。右上角登录和注册按钮只打开 Bootstrap 模态框，独立 `/login`、`/register` 页面仍作为可访问的备用入口。

管理员通过交互式管理命令创建，密码输入不会回显：

```powershell
uv run python -m app.cli create-admin
```

命令使用当前 `ENV` 对应的数据库，运行前应确认环境和迁移已经就绪。公开 `/api/users` 注册接口始终创建普通用户，不能通过请求体传入 `is_admin`。

## Redis Refresh Token 与空闲过期

认证现在使用无状态短期 Access JWT 加 Redis 有状态 Refresh Session：

| 配置 | 作用 |
| --- | --- |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | Access Token 有效期，例如调试设为 `2` 或 `5` |
| `REFRESH_TOKEN_EXPIRE_MINUTES` | Refresh Session 绝对最长寿命，持续操作也不能超过此时间 |
| `REFRESH_IDLE_TIMEOUT_MINUTES` | 连续未执行 Refresh 的最大时间，超过后 Refresh Token 失效 |
| `AUTH_COOKIE_SECURE` | 本地 HTTP 调试设 `false`，生产 HTTPS 必须设 `true` |

登录接口把 Access Token 返回 JSON，并把随机 Refresh Token 写入 `HttpOnly` Cookie。Redis 只保存 Refresh Token 的 SHA-256 摘要和最小会话数据，Key TTL 自动清理过期会话。普通 Bearer 请求不访问 Redis；Access Token 过期时前端调用 `/api/auth/refresh`，Lua 原子轮换 Cookie 并更新 `last_activity_at`。连续未刷新超过空闲期限或达到首次登录的绝对截止时间后必须重新登录。

新增文件和职责：

| 文件 | 用途 |
| --- | --- |
| `app/db/redis.py` | 共享异步 Redis 连接池和依赖 |
| `app/services/refresh_sessions.py` | 创建、原子轮换和撤销 Redis Refresh Session |
| `compose.redis.development.yaml` | 本地 Redis 7、AOF Volume 与健康检查 |
| `app/routers/api_auth.py` | `/refresh` 换 Token、`/logout` 撤销 Redis 会话并清 Cookie |
| `app/dependencies/auth.py` | 只验证 Bearer JWT 和数据库用户，不访问 Redis |
| `migrations/versions/c56c4d6eeba7_drop_refresh_sessions_table.py` | 删除已被 Redis 替代的旧表 |
| `app/static/js/api.js` | 401 时刷新 Access Token 并保存新值 |

Docker Desktop、Redis 容器与 FastAPI 的启动边界，以及本地 Redis 的首次启动、日常启停、AOF Volume、日志和故障排查，见 `docs/Docker启动Redis操作手册.md`。

调试时可以在 `.env.development` 或当前 PowerShell 会话中覆盖时间：

```powershell
$env:ACCESS_TOKEN_EXPIRE_MINUTES = "2"
$env:REFRESH_IDLE_TIMEOUT_MINUTES = "5"
$env:REFRESH_TOKEN_EXPIRE_MINUTES = "30"
```

配置优先级是系统环境变量高于环境文件，因此不用修改代码即可测试短时过期。修改配置后要重启 FastAPI 进程；已经签发的旧 Token 不会自动改变过期时间。

配置文件自身已添加用途说明。`alembic.ini` 是例外：Alembic 在当前 Windows 环境按系统 GBK 编码读取 INI，直接写入 UTF-8 中文会导致迁移命令解析失败，因此该文件保留 ASCII 注释，对应中文解释如下：

- `script_location`：指定迁移脚本目录，`%(here)s` 表示以 `alembic.ini` 所在目录为基准。
- `prepend_sys_path`：把项目根目录加入模块搜索路径，使迁移环境能够导入 `app`。
- `sqlalchemy.url`：故意不写入 INI，由 `migrations/env.py` 从 Settings 读取，避免提交数据库凭据。
- `[loggers]` 及后续配置：只控制 Alembic CLI 日志，不影响 FastAPI 应用日志。

### 创建用户调用链

```text
POST /api/users
  → UserCreate 校验 username、email、password
  → api_users.create_user() 注入 Session
  → services.users.create_user()
      → 规范化邮箱
      → 检查用户名与邮箱
      → 使用 Argon2 哈希密码
      → INSERT + COMMIT + REFRESH
  → UserResponse 过滤 password 和 hashed_password
  → 201 Created
```

数据库唯一约束仍是并发安全的最终保证。Service 中的预查询用于提前给出友好错误，`IntegrityError` 捕获用于处理两个并发请求同时通过预查询的情况。

### 当前接口

```text
POST   /api/users             创建用户
GET    /api/users             分页列出用户
GET    /api/users/{user_id}   查询用户
PATCH  /api/users/{user_id}   部分更新用户
DELETE /api/users/{user_id}   删除用户
```

当前尚未实现 JWT 和认证依赖，因此用户接口暂时公开，只适合开发环境。文档不能把未来计划中的认证描述成已经具备的能力。

JWT 与认证的待开发技术方案见 `docs/JWT与用户认证开发流程.md`。该文件是实施计划，认证完成并通过测试前不能将其中的权限能力视为项目现状。

## 新功能开发步骤

1. 明确请求字段、响应字段、状态码和不在本次范围内的功能。
2. 阅读相关 Router、Schema、Service、Model、迁移和测试，确认完整调用链。
3. 先更新 Schema 与 Model 设计，确保字段长度、空值和唯一约束一致。
4. 数据库结构有变化时新增 Alembic Migration，不修改已应用的旧迁移。
5. 在 Service 实现业务规则和事务，在 Router 中只处理 HTTP 行为。
6. 为新模块添加中文模块 docstring，为公共类、函数、端点和复杂配置添加中文说明。
7. 使用隔离测试数据库覆盖成功路径及相关的冲突、404、422 等失败路径。
8. 更新接口文档、数据库文档和本文的文件用途及调用链。
9. 执行静态检查、目标测试、完整测试和迁移检查，再报告结果。

## 2026-07-27 统一异常处理

| 文件 | 功能 |
| --- | --- |
| `app/exception_handlers.py` | 区分页面与 `/api/` 请求，集中处理 HTTP、参数校验和未知服务器异常 |
| `app/main.py` | 在应用组装阶段注册统一异常处理器 |
| `app/templates/error_401.html` | 未登录或身份失效页面 |
| `app/templates/error_403.html` | 已登录但权限不足页面 |
| `app/templates/error_404.html` | 页面或资源不存在页面 |
| `app/templates/error_500.html` | 未知服务器异常页面，不显示内部错误细节 |
| `app/static/js/api.js` | 从统一 `error` 对象读取接口错误，同时兼容旧 `detail` 格式 |

页面异常链路：Router 或框架抛出异常 → `app/exception_handlers.py` 判断为页面请求 → 选择对应模板 → 保留原 HTTP 状态码返回 HTML。`401` 表示身份未确认，`403` 表示身份有效但权限不足。

API 异常链路：`/api/` Router、依赖或参数校验抛出异常 → 统一处理器转换为以下 JSON。未知 `500` 会在服务端日志记录完整调用栈，但响应只返回通用提示，避免泄露代码、数据库或凭据信息。

```json
{
  "success": false,
  "code": 40401,
  "message": "Post not found",
  "data": null,
  "meta": {
    "requestId": "949dbb1e-8e60-4f43-a3b7-519fcf8b43f4",
    "timestamp": "2026-07-28T00:00:00+00:00"
  },
  "errors": null
}
```

参数校验失败时 `errors` 是由 `field`、`message`、`type` 组成的字段错误数组；其他异常通常为 `null`。错误业务码采用“HTTP 状态码 × 100 + 1”的基础规则，例如未认证为 `40101`、不存在为 `40401`、参数校验失败为 `42201`。HTTP 状态码仍保持 `401/404/422` 等真实语义，不能全部改为 200。

## 2026-07-28 统一 API 成功响应

所有业务 API 成功响应使用以下结构：

```json
{
  "success": true,
  "code": 0,
  "message": "ok",
  "data": {},
  "meta": {
    "requestId": "949dbb1e-8e60-4f43-a3b7-519fcf8b43f4",
    "timestamp": "2026-07-28T00:00:00+00:00"
  }
}
```

| 文件 | 功能 |
| --- | --- |
| `app/schemas/api.py` | 定义泛型 `ApiSuccess[T]` 和 `ResponseMeta`，让 OpenAPI 保留 `data` 的具体类型 |
| `app/api_responses.py` | 统一构造成功响应，写入请求 UUID 和带时区 UTC 时间 |
| `app/main.py` | 请求进入应用时生成 UUID，并通过 `X-Request-ID` 响应头返回 |
| `app/routers/api_auth.py` | 登录、刷新和退出返回统一结构；退出由无正文的 204 改为 200 |
| `app/routers/api_posts.py` | 帖子、列表、图片上传和删除返回统一结构；删除改为 200 |
| `app/routers/api_users.py` | 用户增删改查返回统一结构；删除改为 200 |
| `app/static/js/api.js` | AJAX 公共层自动解包 `data`，业务脚本无需感知响应信封 |

成功响应链路：请求进入中间件生成 `request.state.request_id` → Router 调用 `success_response()` → 泛型 Schema 校验业务数据 → FastAPI 序列化响应 → 中间件写入相同的 `X-Request-ID` Header。

三个 API Router 还会复用 `API_ERROR_RESPONSES`，使 Swagger 中的常见失败状态引用 `ApiFailure`，避免运行时已经统一、OpenAPI 文档却仍展示 FastAPI 默认错误结构。页面 Router 不使用该声明，继续返回 HTML 错误页。

Service 返回 SQLAlchemy ORM 对象时，Router 会先调用 `PostResponse.model_validate(post)` 或 `UserResponse.model_validate(user)` 转为公开响应 Schema，再传给 `success_response()`。这一步利用 `from_attributes=True` 读取 ORM 属性，同时保证 `ApiSuccess[PostResponse]` 等泛型返回类型与实际数据一致，并阻止 ORM 内部字段进入响应。

`POST /api/auth/token` 是博客前端使用的统一响应接口。Swagger OAuth2 必须读取顶层 `access_token`，因此另外使用不展示在业务 API 文档中的 `POST /api/auth/oauth2-token`；它只服务 OAuth2 协议兼容，认证、密码校验和 Cookie 签发逻辑与业务登录完全复用。

HTTP `204 No Content` 按规范不能携带 JSON 正文，所以用户删除、帖子删除和退出登录改为 `200 OK`，其 `data` 为 `null`。这属于公开 API 契约变化，调用方必须同步更新状态码和数据读取方式。

### 登录状态首屏显示

`app/templates/layout.html` 在 `<head>` 中同步读取本地 Access Token，并在页面正文解析前向 `<html>` 写入 `data-auth-state`。`app/static/css/site.css` 根据该状态直接显示对应的导航操作，避免刷新时先出现“登录/注册”、随后再切换成“发布帖子/退出”的闪烁。`app/static/js/auth.js` 仍负责实际登录、注册和退出行为；首屏标记不是后端授权依据，受保护接口仍必须验证 JWT 与用户权限。

`app/exception_handlers.py` 注册处理器时转换为 Starlette 的 `ExceptionHandler` 类型。这只用于解决该类型同时包含 HTTP 与 WebSocket 签名而造成的 Pylance 联合类型误报，不改变异常处理行为。
