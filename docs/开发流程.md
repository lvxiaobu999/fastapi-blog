# 开发流程与模块说明

本文只描述当前代码，不记录重复的日期流水账。详细原理放在专题文档；本文负责让开发者快速定位入口、理解请求链并完成一次安全改动。

## 1. 当前请求链

```text
页面 / 客户端
  -> Router：绑定参数、Depends、权限、状态码
  -> Schema：校验输入、过滤输出字段
  -> Service：业务规则、查询、外部服务和事务
  -> Model / AsyncSession / Redis
  -> Router：组装 HTML 或统一 API 响应
```

Router 不写业务 SQL，Service 不返回 HTTP 异常，Model 不承担请求校验。页面 GET 只准备首屏数据；登录、发帖、互动和资料修改由 `app/static/js/` 调用 `/api/`。

## 2. 目录职责

| 目录/文件 | 当前职责 |
| --- | --- |
| `app/main.py` | FastAPI 组装、生命周期、Trusted Host、安全响应头、健康检查 |
| `app/routers/pages.py` | Jinja 页面和页面级 404/403 |
| `app/routers/api_*.py` | JSON API 的参数、认证、授权、状态码和响应模型 |
| `app/routers/comments.py` | 评论历史 HTTP 接口和 WebSocket 协议 |
| `app/dependencies/auth.py` | Bearer JWT、当前用户和管理员依赖 |
| `app/schemas/` | Pydantic v2 请求/响应契约；响应不得包含密码或 Secret |
| `app/services/` | 可注入 `AsyncSession` 的业务与持久化逻辑 |
| `app/models/` | SQLAlchemy 2 ORM、关系和数据库约束 |
| `app/db/session.py`、`app/db/redis.py` | 异步连接池和 FastAPI 依赖 |
| `migrations/versions/` | 所有持久化结构变更；已应用迁移不直接修改 |
| `tests/` | 使用内存 SQLite 和 fakeredis 的隔离测试 |

## 3. 已实现功能链

### 认证

```text
POST /api/auth/token
  -> OAuth2PasswordRequestForm
  -> Argon2 校验（工作线程）
  -> 短期 Access JWT
  -> Redis Refresh Session（HttpOnly Cookie）
```

受保护请求只验证 JWT 并查询用户；刷新时才访问 Redis。修改密码、设置密码、删除账号会撤销相关 Refresh Session。Access JWT 无法在退出后立即撤销，所以生产应保持短有效期。

### 文章与分类

公开页面和 `GET /api/posts` 只读取已发布文章；管理员 API 负责创建、编辑、上下架、删除和图片上传。文章分类是多对多关系，Service 会批量确认分类存在，数据库联合主键负责防重复关联。

### 互动与评论

文章详情读取互动状态；打开详情会原子增加浏览量，登录用户同时更新足迹；点赞和收藏使用数据库 upsert/删除切换。评论先 GET 历史记录，再连接 `/api/posts/{post_id}/comments/ws`，首条消息必须携带 Access JWT，成功提交后才广播。

### 统一响应和日志

`app/api_responses.py` 生成 `success/code/message/data/meta` 信封；`app/exception_handlers.py` 将 `/api/` 错误统一为 JSON，页面错误渲染 HTML。`main.py` 为每次请求生成 `X-Request-ID`，日志支持文本或 JSON；未知异常只在服务端记录完整堆栈。

## 4. 配置与数据边界

- 配置优先级：系统环境变量 > `.env.<ENV>` > `.env` > 代码默认值。
- 开发使用 `sqlite+aiosqlite`；生产使用 `postgresql+psycopg`，Redis 使用 `redis://` 或 `rediss://`。
- 生产 `ALLOWED_HOSTS` 必须是明确主机名；`AUTH_COOKIE_SECURE=true`，临时公网 IP 模式才允许 HTTP Cookie。
- 密码只保存 Argon2 哈希；Refresh Token 只保存摘要；API 不返回 `password`、`hashed_password`、Secret 或完整内部 Token。
- 用户上传保存在 `app/media`；静态资源随镜像发布。迁移前确认数据库目标和备份，不使用 `create_all` 代替 Alembic。

## 5. 一次功能改动的顺序

1. 阅读相关 Router、Schema、Service、Model 和测试，确认完整调用链。
2. 先修改数据约束和 Migration，再同步 Schema、Service、Router、前端和测试。
3. 为成功路径及相关 400/401/403/404/409/422/503 路径补测试。
4. 检查事务：一个写操作集中提交；已处理的数据库异常回滚；需要数据库生成值时 `refresh()`。
5. 更新对应的专题入口或本文件的功能链，避免复制长篇说明。

## 7. 当前限制与后续优化

这些是已知边界，不应在文档中描述成已解决：

1. 文章搜索使用 `ILIKE`，数据量增长后应评估 PostgreSQL 全文检索和索引。
2. 列表接口只有 `offset/limit`，没有总数和游标；后台数据增长后应补充分页元数据。
3. 图片仍保存在单机目录；多实例前需要对象存储和备份恢复演练。
4. WebSocket 房间只在单进程内存中；扩容前需要 Pub/Sub 或专用消息层。
5. 正式 Compose 当前使用 PostgreSQL 16，而项目目标约定为 PostgreSQL 17；升级大版本前必须备份并在独立环境验证迁移。
6. 生产上线前仍需补齐隐私政策、用户协议、公安联网备案等与实际运营相符的合规页面。
